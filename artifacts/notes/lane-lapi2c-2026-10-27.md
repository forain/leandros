# lane lapi2c phase 1 (2026-10-27/28): PARTIAL

Design: artifacts/notes/design-lapi2c-2026-10-27.md. Scope: probe only (no input node, no Input Mode switch, no evdev/uinput/libinput work).

## Delivered
- `acpi_power::with_ns` (power.rs + mod.rs, additive, ~8 lines).
- `drivers/src/i2c_acpi.rs`: scan of every device under the LPSS I2C controllers (`_ADR` 0x0015000x / 0x0019000x): `_STA`, `_HID`, `_CID`, `_CRS` walk (I2cSerialBus, GpioInt, Extended IRQ), HID-I2C `_DSM` descriptor register, `SSCN`/`FMCN` timings; `_PS0` of the controller and of live devices is run first.
- `drivers/src/dw_i2c.rs`: polled DesignWare master behind 8086:9d60..9d63 (LPSS reset release at 0x204, comp_type check, FIFO depth from COMP_PARAM_1, FMCN/SSCN timings with 120 MHz fallbacks, write-then-read with repeated start, 50 ms timeout, TX_ABRT_SOURCE as error).
- `drivers/src/hid_desc.rs` + `drivers/hid-desc-tests` (4 host tests, one guard shown failing first): descriptor parser keeping item kind/extents/units/logical collection link, PTP extraction, one-line summary.
- `drivers/src/i2c_hid.rs`: for each live PNP0C50 slave: HID descriptor (30 B hex, vid/pid, rd_len, regs), SET_POWER ON + RESET + ack, report descriptor (length, crc32, summary), then a 120 s report counter (`ki2chid` thread in kernel/src/lappower.rs, 10 ms polls; logs the first 4 reports and a final count).
- Knobs: `i2c=0`, `i2c_hid=probe` (default) / `0`, `i2c.debug=1`. `i2c_hid=1` only logs that it is not built yet.

## Evidence
- x86_64 QEMU (TCG): boots clean, `[I2C] i2c: no LPSS I2C controllers`, vfstest PASS. aarch64 QEMU: vfstest PASS (modules are x86_64-only except hid_desc).
- Host: `cargo test --manifest-path drivers/hid-desc-tests/Cargo.toml --target <host>` 4/4.
