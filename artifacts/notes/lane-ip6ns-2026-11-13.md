# lane/ip6ns (design-ipv6 L8) 2026-11-13: PARTIAL (veth/vif v6 + backstop removed; bridge6, tun6, NS-proxy open)

- tunbe.rs: Vif gains `addrs6`; link-local (EUI-64 from MAC) while the link is up, static addresses via RTM_NEWADDR/DELADDR AF_INET6 in ANY netns (CAP_NET_ADMIN gate as v4), pushed into the vif's smoltcp stack (`sync_addrs` keeps v4+v6, `resync` after SetLink). `addrs6(ns)` / `routes6(ns)` feed RTM_GETADDR / GETROUTE dumps (nlsock.rs); `route6_in_ns` = longest on-link global prefix; `sid_by_ifindex` makes scope ids work for vifs (ip6::scope_sid).
- iface::route_select and udp_stack: v6 destinations in a netns (and vif prefixes in ns 0) resolve to the vif stack; unroutable stays ENETUNREACH. The sendto "v4-only backstop" (ip6nswake) is removed.
- listen.rs stacks_for: in a netns a listener on a specific (non-loopback) address now lands on the netns's stacks (it got none before: v6 or v4 explicit-address listeners in a netns were unreachable).
- Tests: brtest `veth6` (host fd00:6::1 <-> child netns fd00:6::2: addr add, ping6 both ways, TCP echo) RED on tests-only commit (addr add + all traffic fail), green after (Mac a64 HVF 7/7). ip6test `ns_udp6_lo` (UDP over ::1 in a netns, unroutable global = ENETUNREACH) was already green: ::1 per netns existed after ip6lo/ip6nswake.
- Open: `bridge6` (33:33 flooding on l2.rs not checked/tested), `tun6` (IFF_TUN 0x86DD framing / NS proxy in tunbe.rs), gateway/default v6 routes on vifs (AddRoute6 in a netns still EOPNOTSUPP), DAD, v6 ndisc cache of bridged ports, notifications. Child netns reaping of v6 state is via the Vif itself (no side table).
