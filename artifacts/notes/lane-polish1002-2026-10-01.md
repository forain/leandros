## 1. Build robustness (container probe)
- `scripts/container-lib.sh` (new) holds the bounded probe. It tries podman first, then docker. `info` must answer within `LEANDROS_CT_TIMEOUT` (20 s). The probe runs once per build-all, and the verdict is cached in `LEANDROS_CONTAINER` (`podman|docker|none` can also be forced).
- ports/firefox, ports/portal, ports/pipewire and ports/mesa/build-gpu-stack.sh all use it.
- build-all `stage_container_port`: when no container answers or staging fails, build-all reuses a packaged tree. It looks for a `.stamp`'ed tree in this order: the worktree's own `out/<arch>`, the main checkout's `out/<arch>`, then `$LEANDROS_ARTIFACTS/<name>-out/<arch>`. If none exists, build-all stops with a clear message; `LEANDROS_SKIP_<PORT>=1` builds without the port.
- Mac (Docker hung): the probe returned in 4–9 s and all 3 ports were reused (firefox from the main checkout, portal and pipewire from artifacts). Build rc 0.
- Desktop: podman staged Firefox. The portal backend can't build there, so it fell back to `$ART/portal-out/x86_64`, which I seeded on the desktop from the Mac.

## 4. Single writer (chosen over routing console players through PipeWire)
- The audio server now accepts one writer at a time, like an ALSA hw PCM without dmix.
- How it works: the VFS sends VFS_OPEN to devices registered with `register_device_notify_open`, and a negative reply fails the open. Writes now carry the open_id. Ownership is either the open (released by VFS_CLOSE) or the IPC tgid (released lazily once that process is dead).
- `aplay` prints "audio device busy" and exits 1. `leandros-snd-sink` waits on EBUSY instead of exiting; it was rebuilt via desktop podman and swapped into the full Mac artifact trees, because a desktop rebuild of the port drops cosmic-applet-audio.
