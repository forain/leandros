## vainfo (root, iHD)
Pushed `iHD_drv_video.so`, `libigdgmm.so.12`, `vainfo` and `ffmpeg` from
`ports/firefox/out/x86_64`. vainfo also needs **`libva-wayland.so.2`**, which is
staged there but was not on the stick (it failed with rc 127, "Error loading
shared library libva-wayland.so.2"), so that was pushed too.

Then the wayland and x11 displays fail (root has no session env), and the drm
display works: `va_openDriver() returns 0`, `Driver version: Intel iHD driver
... 24.4.3`. Supported: only `VAProfileNone: VAEntrypointVideoProc` and
`VAProfileNone: VAEntrypointStats`. There are **no decode profiles**, which fits
`HAS_BSD = has_class(VIDEO)`, still 0 while vcs0 is kernel only (P4). rc 0.

In the klog, i915 uapi `errors` went from 19 to 21 during vainfo (+create 36).
Neither error was logged at the default `i915.uapi_log=1` or recorded as `last`,
so both were probe answers (EINVAL, ENODEV or ENOENT). Seeing which ioctls needs
`i915.uapi_log=2` on the cmdline; not done, because `--cmdline` replaces the
args that carry the Wi-Fi credentials. The only `[DRM] unimplemented ioctl` this
boot was DRM_IOCTL_GET_CLIENT (nr 5) from the greeter (pid 50), before vainfo.
