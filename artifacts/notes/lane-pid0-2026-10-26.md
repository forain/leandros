# Lane pid0 — BCM2712 D0 device tree on the card, C1 vs D0 audit (2026-10-26)

Status: FIXED (card + uart fallback); audit found nothing else to change.

## Card
`scripts/prepare-rpi5-sdcard.sh` (direct boot) now copies both `bcm2712-rpi-5-b.dtb` (C1) and
`bcm2712d0-rpi-5-b.dtb` (D0) to the boot FAT, fetched from raspberrypi/firmware at pinned commit
88a0ae88 (was: unpinned master) and sha256-checked. The C1 file is byte-identical to the one every
rpi5 lane decoded (sha256 03ce4742...). config.txt names no `device_tree`, so the firmware picks
per stepping. The limine/UEFI mode still copies only its vendored C1 dtb.

## C1 -> D0 dts diff (complete, phandles excluded)
- uart10 `interrupts` SPI 121 -> 120 (piirq3 line probe; now also a DT fallback in gic.rs).
- pinctrl@7d504100 `brcm,bcm2712c0-pinctrl` -> `bcm2712d0-pinctrl`, reg size 0x30 -> 0x20; mux/pad tables differ.
  sdio_host.rs D0_PINS checked against Linux rpi-6.12.y pinctrl-bcm2712.c: gpio28 (2,4,5,10) fsel 0,
  gpio30..35 mux reg 2/3, pads reg 5 slots 12..14 / reg 6 slots 0..2, sd2 = fsel 1, pulls none/up. Correct.
- pinctrl_aon@7d510700 compatible c0 -> d0, reg 0x20 -> 0x1c; gio_aon bank widths 17 -> 15. Unused by us.
- gio@7d508500: only line-name labels; WL_ON still gpio 28, reg/widths unchanged.
- DMA channel numbers for hdmi0/hdmi1/spi10; vc4 compatible gains `brcm,bcm2712d0-vc6`. Unused by us.
- Unchanged on D0: sdio2 (0x10_0110_0000/0400, SPI 274), sdio1, v3d (hub/core0/sms, INTIDs 281/282),
  pcie2 (0x10_0012_0000, SPI 233/234), MIP0 (0x10_0013_0000, msi 0xff_ffff_f000), rescal, sw-init,
  mailbox 0x7c013880, GIC-400 0x7fff9000, arch timer PPIs, power 0x7d200000.
