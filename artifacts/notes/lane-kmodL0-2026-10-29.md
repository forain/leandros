## Running menuconfig
    ./scripts/menuconfig.sh --arch x86_64      # or aarch64; edits ./.config (gitignored)
    ./scripts/menuconfig.sh defconfig rpi5     # .config from configs/rpi5_defconfig
    ./scripts/menuconfig.sh olddefconfig       # refresh .config after Kconfig changes
Needs python3 + curses only (kconfiglib 14.1.0, ISC licence, vendored unmodified in scripts/kconfig/).
build-all.sh uses ./.config if it exists, else configs/<target>_defconfig
(aarch64 --rpi5 -> rpi5; INTEL=1 on x86_64 -> x86_64_laptop; else <arch>). Arch comes from
`--arch` (Kconfig sees $(ARCH)), so one .config serves both arches.

## Conventions for L1a/b/c
- Kconfig symbols are in Kconfig, drivers/Kconfig, drivers/usb/Kconfig. CONFIG_FOO_BAR <-> kernel cargo feature `drv-foo-bar`.
- to-cargo.py only passes a `drv-*` feature if kernel/Cargo.toml declares it in [features]; so a lane adds
  `drv-e1000e = ["drivers/e1000e"]` (and the drivers feature) and the plumbing starts passing it. Symbols that no
  feature exists for yet are inert. All defconfigs are all-Y, so every declared drv-* feature is ON by default;
  the lane must make "feature on" == today's code, and add `default = [...]`/drv-all if bare cargo must match.
- Board/special: BOARD_RPI5->rpi5, BOARD_RASPI4B->raspi4b, NVIDIA->nvidia (default n; build-all --nvidia still works).
- `=m` (once symbols become tristate) goes to target/kconfig-<arch>/kmod-list.
- Not done: drivers/src/lib.rs was NOT split into per-group include files (kmodB suggested it to avoid L1 conflicts).
