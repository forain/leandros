## OPEN (next lane): the volume layout and the version bitmaps
1. Our mkfs (mkfs-f2fs-home.py, mkfs-f2fs-populated.py SEG_CNT_SIT=1) makes ONE SIT segment. Linux mirrors
   SIT and NAT (2 copies, choice per block in the cp's sit/nat version bitmap, bytes at cp+192);
   sit_ver_bitmap_bytesize = ((sit_segs/2) << log_bps)/8 = 0 for one segment, and 7.2 requires
   bytesize*8 >= ceil(main_segs/55). So mkfs must use 2*ceil(sit_blocks/bps) SIT segments. Existing volumes
   (stick, /home) can never be Linux-mounted without a relayout.
2. The kernel ignores the version bitmaps (sit_entry_loc = sit_blkaddr + seg/55, copy 0 only; cp_buf
   bitmaps written as zero). Once Linux writes, current SIT/NAT blocks live in copy 1 and our mount reads
   stale copy-0 blocks => "Linux wrote, LeandrOS mounts" is NOT safe yet (not tested: the Linux mount
   never got that far). Fix: at mount, for every set bit copy copy-1 -> copy-0 (through the journal), and
   commit zero bitmaps.
3. fsck.f2fs "Wrong layout" unexplained (fsmeta = 2+1+2+rsvd 2+1 = 8, ovp 1); also both Linux and fsck
   print "Fix alignment: start(3584) end(16896)": segment_count 32 vs 31 segments actually laid out.
   Re-check after 1.
