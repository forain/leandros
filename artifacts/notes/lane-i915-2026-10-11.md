# lane/i915 — 2026-10-11 — Intel UHD 620 (Kaby Lake-R, 8086:5917): probe, execlist bring-up, UAPI foundation

Branch `lane/i915` from main `571ce20`. Not pushed, not merged. Target: the
i5-8350U laptop (Gen9.5 GT2, Sunrise Point-LP, eDP), booted from a USB stick
via UEFI + Limine with only the GOP framebuffer. End goal: Mesa iris (GL/GLES)
and ANV (Vulkan) on an i915-compatible kernel UAPI, KMS on the eDP, COSMIC on
the GPU (the GPU-only rule: init refuses the graphical login without a
hardware GL_RENDERER).

**Nothing here has run on Intel hardware yet. QEMU cannot emulate an Intel
GPU.** What QEMU proves: both arches build and boot to a shell with the code
in, the driver is silent without the hardware, and the whole bring-up path
(including the hang detector, state dump and engine reset) runs to completion
and returns in under 200 ms against fake registers (`i915.fake=1`).

## 3. Command line

Probe only is the default. Everything that touches an engine is opt-in.

| option | effect |
|---|---|
| (none) | G0 probe, ~0.5 s (GGTT scan bounded at 400 ms); engines untouched |
| `i915.off=1` | nothing at all |
| `i915.probe=0` | skip the probe's logging (bring-up still runs if asked) |
| `i915.ggttscan=0` | skip the GGTT occupancy scan |
| `i915.dumpvbt=0` | no base64 VBT in the log (default on, ~11 KB of log) |
| `i915.selftest=LIST` | comma list of `store`, `blt`, `fb`, `rcs`, or `all` |
| `i915.start=1` | bring-up + `store` (until the UAPI backend exists) |
| `i915.reset=0` | skip the GT reset before the bring-up |
| `i915.timeout_ms=N` | per-request budget (default 500; stall limit = half) |
| `i915.selftest_hold_ms=N` | how long the fb bars stay before boot continues (1500) |
| `i915.ggttbase=0x..` | GGTT window for kernel objects (default: top 16 MiB) |
| `i915.fake=1` | testing: bring-up against RAM posing as registers (QEMU) |

## 4. First laptop boots — what to run and what to grep

Stick: `LEANDROS_USB_EXTRA_CMDLINE="..." ./scripts/write-usb.sh x86_64 /dev/diskN`,
or edit the `cmdline:` line of `limine.conf` on the stick's EFI partition.
Log: `scripts/read-usb-log.sh`, then `grep '\[i915\]'`.

**Boot 1 — default (probe only).** Expected, in order:
- `identified: Kaby Lake GT2 Mobile (KBL-R ULT, UHD Graphics 620) ... the target laptop's UHD Graphics 620`
- `BAR0: mem64 non-prefetchable ... size=16 MiB (GTTMMADR ...)`, `BAR2: mem64 prefetchable ... 256 MiB (GMADR ...)`
- `GGC=0x....: GGTT 4 GiB ... stolen 32/64 MiB at 0x...` — note the stolen size and base
- `boot framebuffer phys 0x... = GMADR+0x... -> GGTT offset 0x...` (expect offset 0 or small)
- `display power: ... PWR_WELL_CTL1(BIOS)=... [PW1=on PW2=...]`
- `transcoder eDP: ENABLED ... DDI A DP-SST x2|x4 ...; active 1920x1080 ...` and `GOP scanout: eDP fed by pipe A`
- `pipe A plane 1: ENABLED XRGB8888 Linear ... surface GGTT 0x... == boot framebuffer GGTT offset (OK)` — **a MISMATCH here means the fb self-test will skip itself**
- `pipe A: ... frame counter N -> N+2 or +3 in 40 ms (scanning out)`
- `GGTT: boot framebuffer [...]: ... N/N present, contiguous=1, all in stolen ...=1`
- `OpRegion at 0x...: version 2.x ...`, `VBT "$VBT KABYLAKE..." ... panel_type=...`, `VBT blocks: ...`, then a `-----BEGIN VBT-----` block (decode offline with `base64 -d | intel_vbt_decode --file=/dev/stdin` from igt-gpu-tools)
- `forcewake: acked in gt=.. us render=.. us media=.. us` — **if a domain does not ack, stop and report; nothing GT-side will work**
- `topology: ... slices=0x1 subslices=0x7 (3 total) EUs=24 (8/subslice ...)`
- `CS timestamp: ... -> 12000000 Hz; measured ~12000000 Hz` (the two must agree; Mesa needs this number)
- `GT frequency: ... RP0 1100 MHz ...`
- per-engine lines `rcs0/bcs0/vcs0/vecs0: MODE=... (execlists=0) ...` — expected all idle, legacy mode
- `GGTT scan: ... present in N run(s)` and the first runs
- `=== i915 probe done in N ms (no engine touched) ===`

**Boot 2 — `i915.selftest=store,blt`.** Expected:
`GT reset (GRDOM_FULL): done in N us`, `private PAT programmed: 0x3b2b1b0b00030907`,
`bcs0: execlists enabled: MODE=0x00008000-ish (run-list=1)`,
`self-test store/bcs0: request 1 completed in N us`, `CSB[..] status=... (idle->active ...)`,
`... = 0xc0ffee01 ... PASS`, `bcs0: context image saved by the GPU: RING_HEAD=0x..`,
`self-test blt: square 0 of 4096 pixels wrong, border 0 ... PASS`,
`=== i915 bring-up PASSED ===`. On a hang: the `hang:` line, `faults:` line and
the klog-only `ring[..]` / `context regs[..]` dumps are the evidence; the boot
continues after the engine reset.

**Boot 3 — `i915.selftest=all`.** Adds eight colour bars across the top of
the screen (held 1.5 s; photograph them), `bar centres read back through the
aperture: ff0000 00ff00 0000ff ... PASS`, then `self-test store/rcs0: ... PASS`.

Only the laptop can prove: forcewake acks, that the GOP framebuffer really is
GGTT-mapped stolen memory scanned out by the plane we think, the CS timestamp
rate, that execlists/LRC images/ELSP order/CSB layout are right, that the
blitter reaches the scanout (and through which GTT), coherency of the status
page and scratch writes, RCS context restore-inhibit without the golden
render state, and the reset path on real hangs.

## 6. G3 — what exists and the plan

`uapi_abi.rs` answers, without kernel state: GETPARAM for every id iris/ANV
read (CHIPSET_ID, REVISION, topology masks, EU total, CS_TIMESTAMP_FREQUENCY,
MMAP_GTT_VERSION=4, softpin/no-reloc/handle-LUT/batch-first, context
isolation mask, fence array; PXP/HuC ENODEV); QUERY TOPOLOGY_INFO /
ENGINE_INFO / MEMORY_REGIONS (+ ENODEV for hwconfig/GuC/geometry) with
Linux's length protocol; EXECBUFFER2 checks (softpin only, canonical 48-bit
offsets, engine map or legacy ring selection, fence array); context
GETPARAM statics (GTT_SIZE = 2^48) and the engine-map decoder.

Remaining G3 work, in order (each step testable in isolation):
1. Backend skeleton registered through `gpu_uapi` only after a passing
   bring-up (`i915.start=1`): VERSION "i915" 1.6.0, sysfs PCI identity
   (8086:5917, so libdrm/Mesa's loader picks iris), GETPARAM, QUERY,
   GET_APERTURE, GET_RESET_STATS, REG_READ (RCS timestamp 0x2358, iris'
   `iris_get_timestamp`).
2. GEM: CREATE/CREATE_EXT (memory-regions extension; system memory only),
   GEM_CLOSE, MMAP_OFFSET (WB/WC; one token per object), legacy MMAP,
   SET_DOMAIN/SET_CACHING/GET_CACHING (LLC-coherent; UC for scanout),
   MADVISE, SET/GET_TILING (metadata), BUSY/WAIT, USERPTR (EINVAL first).
   Open question: physically contiguous objects (what the gpu_uapi mmap seam
   supports today) vs page lists — large textures need page lists, as NVK's
   VRAM did not; plan a scattered-page mmap token.
3. VMs and contexts: VM_CREATE/DESTROY = one 4-level `hw::Ppgtt` per VM;
   CONTEXT_CREATE_EXT with SETPARAM (VM, ENGINES, RECOVERABLE, PRIORITY),
   per-(context, engine) LRC image + ring; render contexts need the gen9
   golden state (Linux `intel_renderstate` null batch), the KBL context
   workarounds (LRIs emitted at context init) and the GT/engine workaround
   registers from intel_workarounds.c, plus MOCS and L3CC tables and RPCS.
4. EXECBUFFER2: bind every softpinned object into the context's PPGTT, wait
   in-fences (syncobj via the existing `syncobj_core`), emit invalidate +
   MI_BATCH_BUFFER_START (PPGTT) + breadcrumb into the context ring, ELSP,
   out-fences = `EXT_FENCE` ids answered by a status-page seqno read; a
   watchdog thread built on `HangCheck` marks hung contexts (Linux: banned,
   GET_RESET_STATS counts) and resets the engine. Interrupts (MSI, GT IIR
   user-interrupt bits) replace polling.
5. PRIME export/import for cosmic-comp, then `gputest`-style autotest and
   glmark-like timing.
6. G4 KMS: take over the GOP-left pipe/plane: bind scanout BOs into the GGTT,
   flip by writing PLANE_SURF (+ stride/format for linear/X-tiled) on vblank;
   full modeset (DPLL, DDI training on eDP, PPS, backlight) only later.

## 7. Risks and decisions

- **GTT used by blitter commands in the ring** is not certain (PPGTT vs GGTT);
  the self-test mirrors every address identically in both so either works.
  Scanout pages are mirrored uncached (the display does not snoop the LLC).
- **RCS without golden state/workarounds**: the `rcs` store test uses only
  MI and PIPE_CONTROL; real 3D needs step 3 above.
- **The probe runs on every boot of an Intel GPU** (~0.5 s); writes only the
  forcewake request. `i915.off=1` disables it.
- **Environment**: during this lane the Mac's data disk hit 100% (another
  lane's or Docker's usage; ~125 MB free at worst), so `build-all.sh` could
  not finish here. QEMU verification used this branch's release kernels
  (built with build-all.sh's exact cargo flags + the stack-frame check) in
  small private boot images with the shared initrd/Limine and the shared
  f2fs data images under `-snapshot`. A full `build-all.sh` run is still
  owed before merge. Docker Desktop stopped starting after the Mesa
  container crash.
