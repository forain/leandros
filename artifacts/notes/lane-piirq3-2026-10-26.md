# lane/piirq3 2026-10-26 (openbugs #101: Pi 5 uart10 RX IRQ never fires): line probe + ISPENDR scan + software pend

Result: ROOT CAUSE IDENTIFIED (strong hypothesis, needs one Pi boot to confirm) plus self-correcting probe.

## Cause
BCM2712 **D0** stepping moved uart10's interrupt from SPI 121 to **SPI 120 (INTID 152, 0x98)**:
raspberrypi/linux `arch/arm64/boot/dts/broadcom/bcm2712d0-rpi-5-b.dts` has `&uart10 { interrupts = <GIC_SPI 120
IRQ_TYPE_LEVEL_HIGH>; }`. The firmware gives Linux that D0 DTB. Our card (scripts/prepare-rpi5-sdcard.sh) carries only
the C1 `bcm2712-rpi-5-b.dtb` (SPI 121), and the kernel hardcoded 32+121. The Pi capture fits this exactly: the PL011
asserts (mis 40), and SPI 153 is enabled, level, targeted, but never pending. In the C1 DTB nothing uses SPI 120.
(b) refuted: ISPENDR word 4 bit 25 is the same arithmetic as the `en 1` read. (c) refuted: we drive 0x10_7d001000 = the
dts node. No l2-intc covers uart10. Linux's pl011 "arm,pl011-axi" variant makes no special interrupt writes.

## Change (976f36cf)
- `gic::probe_uart_line` (rpi5 + raspi4b, at GIC init, IRQs masked): it toggles UARTIMSC (0 -> RIS-latched bits -> 0 ->
  restore) and reads GICD_ISPENDR4 bits for INTID 152/153 each time. The INTID that reads 0/1/0 becomes the console UART
  INTID (runtime `uart_intid()`). If it is not 153, it registers `uart_irq` there, enables it and disables 153.
- The rx-pending/init snapshot appends ` spend wN=bits` for every non-zero GICD_ISPENDR word (INTID = 32*N + bit).
- `[uartirq] swpend`: the first kiostat report sets the UART INTID pending, and the next one checks UART_RX_IRQS.
- QEMU raspi4b: `probe ris 20 i98 0/0/0 i99 0/1/0 -> 99`, `swpend intid 99 irqs 0->1 taken 1 pend 0`.
  virt: spend scan shows `w1=2` (INTID 33) at rx-pending. aarch64 virt sigtest/timertest/polltest PASS. check-rpi5 both OK.
