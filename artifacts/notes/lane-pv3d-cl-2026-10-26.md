# lane/pv3d-cl 2026-10-26 (openbugs #98 phase C): real SUBMIT_CL on the Pi 5 V3D

Status: DELIVERED (code + host tests + compile checks + aarch64 regress). Not yet run on a Pi.
Design: `artifacts/notes/lane-piv3d-design-2026-10-26.md` section 2 "Command submission", section 5, row C.

## What landed
- `drivers/src/v3d/queue.rs` (pure, host-tested): `ClQueue`. One bin+render job in flight, strictly in
  submission order (so the global fence watermark `syncobj_retire_fence` stays exact). Bin: invalidate
  (L2TCACTL flush + SLCACTL 0x0F0F0F0F), `PTB_BPOS=0`, QMA/QMS, QTS|EN, CT0QBA, CT0QEA. FLDONE -> render:
  invalidate, CT1QBA, CT1QEA. FRDONE -> optional clean (TMUWCF, then L2TFLS|CLEAN, bounded) -> fence.
  OUTOMEM -> a 256 KiB chunk from a pre-mapped pool (`PTB_BPOA/BPOS`), held by the job until render is done.
  in_sync deps gate bin / render (bin deps gate the render job when there is no bin). Hang timer: every
  500 ms CTnCA/CTnRA must move, else reset = GMP_CFG STOP_REQ + drain poll, SMS RESET_REQ + poll, L2TFL
  range, MMU re-enable (`mmu::reenable`, new) and IRQ masks; the job's fence still signals, `ok=false`,
  GLOBAL_RESET_COUNTER counts it. Nothing allocates or frees in interrupt context (rings reserved up front;
  completed jobs are reaped, BO refs released, in task context).
- `drivers/src/v3d/submit.rs`: `drm_v3d_submit_cl` parsing/validation, MULTI_SYNC (id 1) chain walk
  (wait_stage routing, legacy in/out syncs ignored when present, binary syncobjs only, EFAULT on bad user
  memory), CRC-32, the self-test BO builder; rpi5 glue: queue lock + try-lock servicing from the core IRQ hook,
  the DRM tick (`irq::poll()` when `irq::polled()`), `param()` for GET_PARAM, the boot self-test.
- `drivers/src/v3d/selftest_cl.rs`: GENERATED by `drivers/v3d-tests/tools/gen_selftest_cl.py` (packer
  `clpack.py` follows Mesa's gen_pack_header rules) from Mesa 25.3.6 `cle/v3d_packet.xml`, V3D 7.1. It is
  v3dv's `meta_emit_fill_buffer_rcl`: 64x64 frame, 32x32 tiles, RGBA8UI internal 8ui/32bpp, clear color
  0xCAFE5A3C, two GFXH-1742 dummy tiles, generic tile list storing RT0 raster stride 256. No
  BRANCH_TO_IMPLICIT_TILE_LIST (nothing binned).
- `drm_device_interface.rs` (aarch64+rpi5, only when `v3d::submit::active()`): SUBMIT_CL real path (BO refs,
  syncobj deps, out-syncs + BO fences attached), WAIT_BO reaps retired jobs (wait logic unchanged, it already
  waits on the real fence watermark), GET_PARAM from `REPORT` (identity registers, UIFCFG live) with
  CACHE_FLUSH=1, MULTISYNC_EXT=1, live reset counter, and **TFU=0, CSD=0 on the real device until phase D**.
  The QEMU stub path is untouched.
- `mod.rs`: `after_probe` success -> `submit::after_mmu` (queue up, pool, self-test). Knob `v3d.selftest=0`.
