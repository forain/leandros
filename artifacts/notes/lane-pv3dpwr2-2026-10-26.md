# lane/pv3dpwr2 2026-10-26 (#98, follow-up to pv3d-power): V3D power order, SError survival, opt-in probe

Status: DELIVERED (host tests, compile checks, aarch64 regress). Not yet run on a Pi.

## The first Pi 5 boot (uart10, $SP/piirq/boot.txt)
`[v3d] fail sms-power timeout val=0x00000050 pm=0x00001040->0x00001040 clk=960MHz`, then
`[EXC] Unexpected Exception! ESR=BE000011 ELR=<init entry>` and a wedged cpu0 (`[WDOG] ... no timer tick`).

Findings:
1. **The GRAFX island was never powered.** Both dts (c1, d0): the v3d node has `power-domains = <&pm 1>`
   (phandle 0x4c = `watchdog@7d200000`, `brcm,bcm2712-pm`, the PM block, not the firmware
   `raspberrypi,bcm2835-power` domain driver), `resets = <&pm 0>`, `clocks = <&firmware_clocks 5>`.
   Linux `drivers/pmdomain/bcm/bcm2835-power.c` (master and rpi-6.12.y, read 2026-10-26):
   GRAFX_V3D (1) is a genpd **subdomain of GRAFX (0)**, so GRAFX powers first:
   `bcm2835_power_power_on(PM_GRAFX=0x10c)`: skip if POWUP already set, else POWUP with inrush
   3.5->20 mA until POWOK, ISPOW, MEMREP + wait MRDONE, ISFUNC. Then GRAFX_V3D on a 2712 (no ASB):
   `bcm2835_asb_power_on(PM_GRAFX_2712=0x304, 0, 0, PM_V3DRSTN)` (pm has no clock -> just 1 us + V3DRSTN).
   The v3d driver then enables firmware clock 5 and runs `v3d_idle_sms` before HUB_IDENT1.
   The old probe skipped the 0x10c step entirely.
2. **SMS STATE is bits [3:0]** (Linux `V3D_SMS_STATE_MASK`), not [4:0]. `0x50` = OLD_MODE 1,
   NEW_MODE 1, STATE IDLE: the "timeout" was a decode bug. The SMS block itself answered.
3. The SError is asynchronous: DAIF.A is masked in the kernel, so it surfaces at the first eret to EL0.
   It cannot be pinned on V3D from this log alone (the sdio2 probe also failed at cmd5 that boot);
   the new checkpoints separate the candidates.

## What landed
- `drivers/src/v3d/power.rs`: `grafx_power_on` (Linux sequence, early-break inrush ramp, every failure
  undone), `pm_confirm` (re-read 0x10c and 0x304 after the clock; requires POWUP|POWOK|ISPOW|ISFUNC and
  V3DRSTN, else `fail pm-confirm mismatch`, no V3D access). Order: GRAFX -> V3DRSTN -> clk 5 -> confirm
  -> SMS -> ident. New steps appended (`grafx`, `pm-confirm`) so PROBE_STATE codes are stable.
- `regs.rs`: PM_GRAFX bits, `sms_state` = [3:0].
- `mod.rs`: opt-in `v3d.probe=1` (default skipped); `probe_boot(.., serror_check)` checks after
  power-up and after MMU/CL (before arming); on an SError: `[v3d] fail serror stage=.. syn=..`,
  DEVICE cleared, not armed, PROBE_STATE=4. Fail/success lines carry `grafx=before->after`.
- `arch/aarch64`: SError vectors (EL1h 0x380, EL0 0x580) save the IRQ-style frame, log
  `[SERROR] from=el0|el1 ESR=.. ELR=.. n=.. (logged, continuing)` (first 16, then every 1024th) and
  return through ret_to_user. `serror_checkpoint()`: dsb/isb, ESB + DISR_EL1 on RAS CPUs (A76 has RAS;
  HCR_EL2 = RW only, so DISR is the real one), else ISR_EL1.A -> brief unmask; also reports SErrors the
  vectors took since the last checkpoint. RAS error records (ERR<n>STATUS/ADDR/MISC0, W1C) only with
  `serror.errrec=1` (EL3 may trap ERR* via SCR_EL3.TERR).
- `kernel/src/init.rs`: rpi5 runs a checkpoint before the v3d probe (`[SERROR] pending before the v3d
  probe ...` blames an earlier probe), then the probe with the checkpoint.
