# lane/pirp1 — RP1 clocks, GPIO, fan, Pi 5 LEDs + power key (2026-10-26)

Status: DELIVERED as code + host tests; NOT hardware-verified (no Pi boot in lane).

## What
- `drivers/src/rp1_hw.rs` — pure register math, checked against the Raspberry Pi Linux 6.12 sources
  (`clk-rp1.c`, `pinctrl-rp1.c`, `pwm-rp1.c`, fetched for this lane) and the bcm2712d0 DTB:
  PLL VCO/prim/sec/pri_ph, clock 16.16 dividers (DIV_INT 0 = 2^16), parent decode (SEL one-hot /
  CTRL.SRC / AUXSRC), RP1 GPIO bank/CTRL/PAD/RIO offsets, PWM RANGE/DUTY as `rp1_pwm_apply`,
  pwm-fan duty, fan curve over the DTB cpu-thermal active trips, brcmstb gio bits, button debounce.
- `rp1_clk.rs` — PLLs read back, never reprogrammed. clk_sys (GEM pclk/hclk) read only.
  clk_eth (125 MHz), clk_eth_tsu (50 MHz), clk_pwm1 (50 MHz): left alone if on, else the first aux
  parent that reaches the DTB assigned rate exactly (pll_sys_sec/1, xosc/1, xosc/1), then ENABLE.
  `rate(id)` for other drivers. If a GEM clock cannot be enabled, macb is NOT attached.
- `rp1_gpio.rs` — kernel API: `function`, `set_function`, `set_pull`, `output`, `input`, `set`, `get`,
  `reset_pulse_active_low`. Replaces pipcie's ad-hoc GPIO32 pulse (same offsets; host test
  cross-checks all 54 pins against `brcmstb_hw::rp1_gpio_regs`).
- `rp1_fan.rs` — GPIO45 alt0 = pwm1 (pinctrl table `PIN(45, pwm1, ...)`), pull-down, PWM1 ch3,
  inverted, range 2078 @ 50 MHz (24 kHz), FIXED level 175/255 (state 3). Tach read from PWM1+0x3c
  (DTB rpm-regmap/rpm-offset) and logged in decimal 5 s after boot.
  TODO(thermal): lane pimisc has no thermal API on main yet; `rp1_hw::fan_state()` is the curve.
- `pi5_board.rs` — ACT LED gio_aon 9 (active low) lit on every SD read/write (wrappers in
  blkdev_sdhci.rs, sdhci.rs untouched), off after 40 ms idle; PWR LED RP1 GPIO 44 set to DTB
  default off once RP1 is up; power button gio 20 (active low, 50 ms debounce) → EV_KEY
  KEY_POWER(116) + SYN on evdev event0 — the node QEMU's virtio keyboard delivers KEY_POWER on
  (the laptop has no power-key path: no ACPI button driver). One `pi5-board` kthread, 50 ms poll.
  Runs on every rpi5 boot (BCM2712 GPIO only, no PCIe); `pi5.board=0` disables it.

## pcie.rpi5 default: stays OFF
The SError handler (pv3dpwr2) covers asynchronous aborts, but not the remaining failure modes
of a never-run bring-up: a stalled AXI read on an unclocked/unpowered RC hangs the CPU with no
exception; resetting pcie2 and RP1 can't be shown harmless without one boot. Flip the default
after one Pi boot shows `[pcie] state=up` and the `[rp1clk]` lines below.

## Expected Pi boot lines
Always (rpi5): `[pi5] act led gio_aon9, power key gio20 (level high = released)`
With `pcie.rpi5=1`, after the pipcie lines (`[rp1] msix vectors=..`):
```
[rp1clk] pll_sys core=1000 MHz pri=200 sec=125 lock=1
[rp1clk] pll_audio core=1536 MHz pri=61 sec=153 lock=1
[rp1clk] pll_video core=... lock=1
[rp1clk] clk_sys 200000000 Hz (pll_sys, was on)
[rp1clk] clk_eth 125000000 Hz (pll_sys_sec, was on|enabled)
[rp1clk] clk_eth_tsu 50000000 Hz (xosc, was on|enabled)
[rp1clk] clk_pwm1 50000000 Hz (xosc, was on|enabled)
[pi5] pwr led rp1 gpio44 off
[rp1fan] pwm1 ch3 gpio45 fsel 0x..->0 range=0x81e level=0xaf/255 (fixed, no thermal yet)
[rp1] eth phy reset pulsed (gpio32)
[macb] attached: ...
[rp1fan] tach <n> rpm        (about 5 s later)
```
Failure forms: `[rp1clk] clk_eth 0 Hz (.., OFF, no parent)` then `[rp1] FAIL gem clocks off, macb
not attached`; `[pi5] FAIL gio map|thread`. Power button press: `[pi5] power key pressed`.
