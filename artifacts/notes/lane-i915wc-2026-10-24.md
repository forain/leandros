## What changed
- `I915_GEM_MMAP_OFFSET` hands out one opaque `drm_offset` value per (BO, mode). The kernel-internal
  real token is `phys | tag` (WB 0, WC 1, UC 2); it never reaches userspace.
- The backend's uncached answer rides bit 0 of the 0x1007 result; servers/drm turns it into
  MMAP_HINT_UNCACHED -> PageFlags::WRITECOMBINE (x86 PAT WC, aarch64 Normal-NC).
- `cpu_wb` is set only by WB maps, so a WC-only scanout flips without a clflush. `/proc/i915` now has
  flips_clflushed, mmap_wb, mmap_wc, mmap_uc.

## Security check (drmtok3 contract)
- Userspace gets `drm_offset::offset_for(phys|tag, size)`, a page-aligned value at >= 16 TiB.
  `handle_ioctl_mmap` refuses non-fake raw offsets for open_id != 0. No physical address leaks.
- Guard: new i915test case `mmap_offsets_opaque_per_mode` (WB/WC/UC offsets >= 1<<44,
  page-aligned, pairwise distinct). It holds by construction, since BO phys is below 16 TiB.
  No negative build was run.
