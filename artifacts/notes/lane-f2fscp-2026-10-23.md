# lane/f2fscp (2026-10-23): f2fs checkpoint never writes in place (L4.11 item 4) - FIXED (partial on extras)

Changes (servers/f2fs/src/durable.rs, lib.rs):
- `cp_in_place` replaced by `cp_emergency`: same journal/commit layout as `cp_prepare`/`cp_write`, zero-copy
  (blocks written straight from the cache), index lists in `dur.emerg_a/emerg_b` preallocated at mount (2*cap).
  If the journal cannot be placed or a write fails: nothing is written in place, blocks stay dirty, returns false.
  `pick_ext` now fills a stack array (no Vec).
- `write_checkpoint`/`flush_checkpoint` return bool; fsync gets EIO (-5) on failure (handle_fsync, checkpoint_unlocked).
- Throttle: `dur.ext_free` (free whole segments, capped 64, recomputed at settle and mount) and `journal_room`;
  `cp_throttle` checkpoints when npinned approaches 3/4 of the journal room (ext_free halved: no allocator decrement,
  free_seg_cnt is not maintained).
- Cache backstop: growth allowed up to 2*CACHE_MAX_SLOTS; data victim preferred (existing). NOT done: the
  doom/cp_wanted retry (step 8b); metadata in-place eviction stays the last resort.
- Side bug: `EVICT_UNFLUSHED` makes the next roll-forward record flush after a backstop eviction write.
- Test knob `f2fs.cpfail=1` (every 3rd cp_prepare fails, /mnt volumes); `f2fscrashtest.py --cmdline`.
