# lane/stdevx86 (2026-10-26) - FIXED

stdev suite failed at boot on x86_64. Cause: extra disks used `disable-legacy=on` (modern virtio 0x1042), while x86's base
disks are transitional/legacy (0x1001). The kernel probes modern virtio-blk before legacy, so the 64M extras became vda/vdb,
and the kernel mounted one as root ("execve /bin/login failed"). Fix: on x86_64 the extras omit disable-legacy (same as base
disks), so PCI-slot order holds and they land after the base disks (vdd/vde); aarch64 unchanged. stdev 9/9 x86_64 (TCG), aarch64 green.
Pinning PCI addr did NOT help (probe order is by modern/legacy, not slot).

Fragility (not changed): kernel root selection logs "/dev/root -> vdb" with no root= hint; root is whichever disk the probe
order yields as the 2nd. Any extra modern virtio-blk disk reorders it. blkmanytest.py uses disable-legacy=on on x86 too and
likely has the same latent problem there (its BASE_DISKS naming is also hardcoded).
