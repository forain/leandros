### 4.1 The A/B on assertion (b) — the patch is provably live

`servers/net` is a kernel-linked crate (`net-server` in `kernel/Cargo.toml`),
and `scripts/m7z2-kernel-only.sh` rebuilds only the kernel and re-embeds it in
`leandros-limine-<arch>.img`, leaving `f2fs-data0-<arch>.img` untouched. That
makes a true single-variable A/B possible: same `/bin/scmtest` binary, two
kernels.

Falsification applied was exactly the one the design doc names — line 2650 of
`servers/net/src/lib.rs`, `if let Some(p) = park { time_wait_add(p); }`,
replaced by `let _ = park;`. Nothing else was touched: not the `handle_bind`
EADDRINUSE check, not `handle_setsockopt`, not `alloc_ephemeral_port`.

`md5 f2fs-data0-aarch64.img` = `0c1e090c4a611e194d329d700500dfbf` **before and
after** the kernel-only rebuild — the data image is byte-identical across both
runs, so the two runs are provably executing the same test binary.

### Does it invalidate anything measured above?

**No, and the reason is not just "pass/fail is robust".** Concretely:

- `drmsmoke`, `vfstest`, `scmtest`, `waittest` and `idletest` are all pass/fail
  on syscall return values. None of them reads `[DRMSTAT]`, and `drmsmoke` in
  particular never touches `FLIPS_SUBMITTED`.
- The one result that *is* timing-shaped is `idletest`, which measures a
  `getrusage` CPU-time delta across a ~3 s idle window. `DRM_STATS` costs a
  serial line every 2 s from the tick, which is charged to the tick, not to the
  test's threads — and it reported `IDLE_CPU_US 0`, the floor, so there is no
  headroom for it to have been flattered. It is re-run below with the flag off
  regardless.
- The A/B on assertion (b) was run with the flag in the *same* state on both
  sides, so it is unaffected by construction.

The flag was **not** touched mid-measurement: every number in §3–§5 was taken
with `DRM_STATS = true`, and the flip happened only after the last of them.
