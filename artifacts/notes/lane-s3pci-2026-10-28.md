# lane s3pci (2026-10-28)

Generic PCI config-space save/restore, `drivers/src/pci_pm.rs` (no S3 entry; inert unless asked).

- Saved per function: command, cache line/latency, BARs, ROM, int line, bridge bus numbers/windows,
  PMCSR, MSI (ctrl/addr/data/mask), MSI-X ctrl + every table entry (read from BAR MMIO), PCIe cap
  (DevCtl/LnkCtl/SltCtl/RootCtl/DevCtl2/LnkCtl2), LTR and L1SS ext caps.
- Restore (Linux order): bridges first (ascending bus), PMCSR to D0 (+10 ms from D3hot), COMMAND=0, header
  descending, COMMAND, then caps, MSI-X last (function-masked while the table is rewritten).
  Bug found by the test: COMMAND must be back on before the MSI-X table write (table is BAR memory).
- Hook: `kernel/src/pm.rs` last `DEVS` entry "pci" (runs after every driver quiesced, restores before any
  resumes). Flags in `PmTestReq`: `PM_PCI`=2 (save, clobber INTLINE/cache line/latency, restore only
  differing registers, verify all dwords), `PM_PCI_DEEP`=4 (unconditional restore incl. COMMAND=0 pulse;
  also clobbers MSI data and MSI-X entry 0). `suspendtest --pci` / `--pci-deep`.
- Not done: PM D3 entry, AER/ACS/other ext caps, PBA, SR-IOV; restore is not wired to real S3 (s3core).
- Tests (release): x86_64 TCG and aarch64 HVF: `--pci` and `--pci-deep` PASS (13 / 10 functions, 263 / 229
  dwords verified, disk_after + display_after pass), plain `suspendtest` unchanged PASS.
