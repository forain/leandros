# lane/herd1, 2026-10-18: keyed evdev wakes

Before this lane, an input event woke every poller in the system: `wake_pollers` called `try_wake_poll`, which is the broadcast.

## Change
- `servers/evdev`: `wake_dev(dev)` sends a keyed wake, `try_wake_poll_key(evdev_poll_key(dev))`. The pending mask is now kept per device. A contended RUN_QUEUE re-arms the device bit, so the wake is retried, not lost. The `VFS_POLL` reply carries the same key.
- `servers/vfs`: a `DynamicDevice` probe now forwards a device server's single exact key (`poll_vnode_k`). An answer that claims keys but does not carry exactly one key falls back to broadcast. It is never reported as foreign.
- Text-VT session readers park on their pty. They are now woken by their PTY tag (`tty_server::vt::kbd_wake_tags`), both for routed keys and for autorepeat. Before, the broadcast covered them.
- Console readers keep working. They park with the broadcast mask, which every keyed wake reaches.
- `/proc/sysstat` `w` lines have a new last column, `pwakes` (`Task::poll_wakes`).
- New regression test `evtest2 herd`, driven by `host:evherdtest.py` in `regress`. It parks a waiter on event0 while the tablet moves, and asserts that the waiter took at most 3 wakes.

## Measured (aarch64/HVF, regress VM, `sched.wakestat=1`, 64 tablet frames / 168 events)
| | evdev wakes | tasks woken | per wake | keyboard waiter woken |
|---|---|---|---|---|
| before | 93 | 1207 | 13.0 | 56 (FAIL) |
| after | 94 | 132 | 1.4 | 0 (PASS) |

- Before: gdwake counted 30 useful wakes and 247 spurious ones.
- After: everything still woken is a broadcast-mask park (allmask 132/132).

## Untested remainder
- **x86_64 regress was not run.** The coordinator wrapped the lane up after the aarch64 run (30/30 PASS).
- These paths were not exercised by any test:
  - A text VT (2..6) session typed on the keyboard.
  - Autorepeat on a text VT.
  - EVIOCREVOKE wake.
  - USB HID and PS/2 devices (dev ids above 1).
  - Laptop desktop.
- Other herd, not fixed: broadcast-mask parks still take every evdev wake. In the regress VM, tgid 36 took 94 spurious wakes during the run. Console stdio pollers and blocking `read()` on a `DynamicDevice` fd (`fd_wake_tag` returns None, so the read parks on the broadcast mask) both park that way.
- Other herd, not fixed: the VT-switch resync in `complete_switch` is still a broadcast.
