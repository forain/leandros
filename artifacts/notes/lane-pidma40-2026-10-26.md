# Lane pidma40 (2026-10-26): BCM2712 dma40 DMA engine

Status: DELIVERED (host-tested and compile-checked; the hardware path is unproven until the next Pi boot).
Lane 3 of `lane-pisound-design-2026-10-26.md`. Commit 2a79afd7 on lane/pidma40.

## What landed
- `drivers/src/bcm2712_dma40/cb.rs` (pure, builds on every arch): the register map and CS/TI/SRCI/DEBUG bits
  copied from Linux `bcm2835-dma.c` (rpi-6.x, the 40-bit variant). It has the 32-byte `Scb`
  (`struct bcm2711_dma40_scb`), 40-bit address split (low byte of SRCI/DESTI), `cb_addr` = addr>>5 (the SCB
  must be below 128 GiB), the DREQ cell decode done the way Linux does (DTB cells `0x41fa000a`/`0x41fa0011` -> PER_MAP 10/17 for hdmi0/hdmi1, not the 12/13 in the
  design note (confirmed by lane pihdmi-probe), QOS 0xa,
  PANIC_QOS 0xf, WAIT_RESP, 128-bit src, burst 3), memcpy chains (1 GiB per SCB), the cyclic mem-to-FIFO ring
  (one SCB per period, the last looping back, D_DREQ, fixed dst), ring position and advance math,
  `pick_channel`, INTIDs (SPI 0x50+n, so ch10 = INTID 122), and start / wait_done / Linux-order abort over
  a `ChanRegs` trait.
- `drivers/src/bcm2712_dma40/mod.rs` (rpi5 only): ioremaps the node window (channel n = 0x10_0001_0000 + n*0x100;
  the node starts at ch6). `claim(prefer)` uses a CAS on the mask and skips channels the firmware still runs
  (CB != 0). Each channel gets a one-page SCB table and an IRQ line. `Channel::{memcpy, start_cyclic, position,
  periods, poll, status, stop}`; Drop aborts, frees and releases. `polled()` reports whether a tick must call
  `poll()`. The engine is not coherent, so `dc civac` runs on SCBs and buffers.
- Boot self-test (rpi5, `kernel/src/init.rs` right after the v3d probe, with an SError checkpoint before it and
  after the copy): claims a free channel (prefers 10), copies 64 KiB between two buddy pages, checks a CRC, then
  frees everything. Inert: one line, bounded at 100 ms. `dma40.selftest=0` skips it.

## Expected next Pi boot
- `[dma40] cs/cb ch6=XXXXXXXX/00000000 ... ch11=...`: a census. A nonzero CB means the firmware owns that channel.
- `[dma40] selftest ok ch=10 bytes=65536 crc=0x........ mode=irq|poll intid=122 src=0x.. dst=0x.. t=..us`.
  `mode=poll` means INTID 122 never fired, and pihdmi-audio must drive `poll()` from its tick.
- Failures are one line each: `[dma40] selftest fail Timeout ch=10 cs=.. debug=..` (the engine is not
  enabled/clocked, probably a global enable the firmware left off), `fail Hw(cs,debug)` (bus error: see
  DEBUG bits 0..3), `fail crc ...` (cache or addressing), `fail serror ...`.
  If src/dst land above 4 GiB, the 40-bit DRAM path is proven too.

## Open
- The dst of the HDMI path is a peripheral (MAI_DATA at CPU 0x10_7c72_001c). `dma-ranges` are the identity, so
  the API takes CPU physical addresses, but Linux vc4 builds the address from the 32-bit `hd` reg cell
  (0x7c72001c). If the first stream gets no data, try the legacy address. This is pihdmi-audio's call.
- No global ENABLE write: the BCM2711-style 0xff0 register lies outside both dma nodes' reg windows.
