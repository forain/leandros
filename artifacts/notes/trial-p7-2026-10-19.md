## Method
- Session started through greetd IPC at uptime 87 s. The profile was clean: user.js holds only the autoplay prefs, and prefs.js has no
  vaapi, hardware-video, dmabuf or ffmpeg entries.
- Each launch kills the old Firefox, starts aqz-KE-bpKQ as leandro, and takes per-thread `/proc/*/task/*/stat` snapshots at +30, +60
  and +90 s after RDD appears. The table uses the +60 to +90 s window (30.7 s). CPU is % of one core. The script is
  scratchpad `p7/t.sh`, the analyser `p7/an.py`.
- "Sink counters": there is no sink counter file in procfs, so `leandros-snd-sink` and `pipewire-pulse` CPU ticks advancing
  (2–3 % each) together with wifi0 RX stand in for them.
- B used a copy of the launcher with the three `LIBVA_MESSAGING_LEVEL`/`MOZ_AV_LOG_LEVEL` default lines replaced by
  `unset` (`/tmp/p7/ffB.sh`). `/proc/<rdd>/environ` confirmed both variables were unset, and `LIBVA_DRIVER_NAME=iHD` was still set.

pipewire-pulse 3.6 % kept running, and RX was 86 KB/s. RDD was 13.6 %, exec_vcs +1813, firefox 30.3 %, total 194 %. **Pass.** Note that decode
did *not* drop with the panel off, unlike the earlier note in remote.md. Afterwards `blanktest --on` restored the panel for B2.
