# lane/tkip — 2026-10-24 (L6.6) — FIXED in code; HW join [needs PSK from user]

WPA/WPA2 mixed-mode networks (LEANDRO2026 / LEANDRO20265G: RSN group TKIP, pairwise TKIP+CCMP,
AKM PSK, no MFP, + WPA1 IE) are now joined the way Linux does it: pairwise CCMP plus a
receive-only TKIP group key. CCMP-group networks are unchanged.

## What changed (commit 1de828a4)
- RSN selection: `select_akm` (wifi_mgr.rs) and `supports_wpa2_psk_ccmp` (wifi_frame.rs) accept
  group TKIP when pairwise CCMP is offered. The "set the router to WPA2-AES" diagnosis is gone.
- Association RSN IE echoes the AP's group cipher (`rsn_ie_psk(group)`). WPA1 IE is not sent.
- Supplicant: `set_group_tkip(true)` means it expects a 32-byte GTK in msg 3 and in group rekeys.
  The descriptor stays v2 (pairwise CCMP).
- Firmware key: 8265-36 has neither API TKIP_MIC_KEYS (29) nor DEPRECATE_TTAK (41), checked
  against the ucode TLVs. So it uses ADD_STA_KEY v1 64 B, TKIP flag 3: key[32] in nl80211 layout
  (TK, own TX MIC = GTK[24..32], own RX MIC = GTK[16..24]), tkip_rx_tsc_byte2 = IV32 low byte,
  TTAK = phase-1(TK, BSSID, IV32 from the RSC). Same as iwlmvm `iwl_mvm_send_sta_key` api_ver 1.
- RX (legacy REPLY_RX_MPDU, same as iwlmvm rx.c): SEC_TKIP (3<<8) with ICV_OK+TTAK_OK means the
  firmware decrypted it. The IV (8) is in front, Michael (8) + ICV (4) behind. If TTAK is missing
  (IV32 moved on, about every 65536 group frames), the host decrypts (phase 1/2 + RC4 + ICV),
  like mac80211's fallback. The host checks Michael. On failure the frame is dropped and logged,
  and a second failure within 60 s is flagged. The real countermeasures (report + 60 s block) are
  NOT implemented. The TSC replay check reads the TKIP IV byte order for group key ids.
- wifi_sim: the `t` (TkipGroup) AP hands out a 32-byte GTK. Its checks flipped to
  `bss-tkip-group-joinable` / `connect-tkip-group`.

- Host tests: 147 -> 156, all green. New: TKIP phase1/phase2/Michael/full M.6.3 MPDU decrypt
