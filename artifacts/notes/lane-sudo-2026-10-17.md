# lane/sudo — su and sudo (2026-10-17)

Goal: from a root SSH login on the laptop, with leandro's COSMIC session up,
start Firefox as leandro (uid 1000, audio through leandro's PipeWire) with both
`su leandro -c '…firefox URL'` and `sudo -u leandro env … firefox URL`.

## What was done

- **sudo-rs v0.2.15 ported** (`ports/sudo-rs`, `e4cfa9cf`): `sudo` and `su`,
  static musl, installed `/bin/sudo` + `/bin/su` 04755 root. PAM =
  pam-leandros (rlib + empty `libpam.a`, as greetd). Five patches:
  1. link pam-leandros, `[workspace]`;
  2. pty follower `chown("/dev/pts/N")` ENOENT is not fatal (VFS keeps no pty
     owner/node) — was "cannot execute '/bin/id': ENOENT" for every command;
  3. `UserTerm::open` (/dev/tty) returns ENXIO unless isatty — our VFS gives a
     stdin proxy for ctty-less sessions; with stdin a pipe every termios call
     was ENOTTY. Falls back to no-pty, as on Linux;
  4. bare `-E` implemented (upstream ignores it): every caller variable as a
     `VAR=value` request ⇒ allowed under SETENV (`ALL` implies it), PATH stays
     secure_path, SUDO_* stay sudo's;
  5. timestamp records in `/run/user/.sudo-rs/ts` (tmpfs) instead of
     `/var/run` (persistent f2fs here).
- **pam-leandros**: `pam_rootok` for services `su`/`su-l` (real uid 0 ⇒ no
  password); `pam_open_session` exports `XDG_RUNTIME_DIR=/run/user/<target uid>`
  for su/su-l/sudo/sudo-i when the dir exists (pam_systemd's job). greetd
  untouched.
- **Image**: `wheel:x:10:leandro` (leandro keeps 1000 29 44 104 108 too);
  `/etc/sudoers` 0440 from `ports/sudo-rs/data/sudoers` (env_reset,
  secure_path, env_keep += WAYLAND_DISPLAY XDG_SESSION_* XDG_CURRENT_DESKTOP
  LANG LC_ALL TERM COLORTERM, timestamp_timeout=5, `root`/`%wheel` ALL);
  `/etc/shells`.
- **Kernel/VFS**: `/proc/<pid>/stat` field 22 `starttime` was the *current*
  uptime in seconds; now the thread-group leader's creation time in ticks
  (`Task::start_ns`). sudo's cache scope is (ppid, starttime) because `tty_nr`
  is always 0 — with the old value the cache key changed every second.
- **brush patch 0005**: brush chdir()s every child into its tracked cwd;
  from root's 0700 `/root` (where SSH root lands) `su leandro -c anything` was
  EACCES for every command. Now only chdir when the process isn't already
  there. **The shared sibling `~/code/brush` was NOT modified** (other lanes
  build from it); this lane built from a private clone
  (`LEANDROS_BRUSH_DIR`). On merge: `ports/brush/sync.sh apply ../brush`
  (or commit 0005 onto its `leandros` branch) or `build_brush`'s sync check
  fails.
- **/etc/profile**: returns right after PATH/XDG_RUNTIME_DIR when `XDG_SEAT`
  is unset (greetd always sets it). Otherwise `su -`/`sudo -i` ran the GPU
  probe, printed "profile: session starting", unset WAYLAND_DISPLAY, and on a
  GPU-less VM hit `exit 78`.

## Tests

`/bin/sudotest` (userland/sudotest, in `--suite regress`): 31 checks as root,
leandro (wheel) and cosmic-greeter (not wheel) — ids + groups, `su -`/`-l`
env, target-password su, env_reset/secure_path/-E/-i/-s, `-S` right/wrong,
`-n` with/without cache, `-K`, `-l`, non-wheel denial, run from 0700 /root,
stable starttime, modes 04755/0440.

- aarch64 (HVF): regress 24/25 + sudotest 31/31 on the re-packed image (the
  regress run's sudotest failed only the /root case: a standalone mkfs run
  without `LEANDROS_BRUSH_DIR` had packed the unpatched sibling brush).
- x86_64 (TCG): regress 25/25 PASS, sudotest 31/31.
- COSMIC session, aarch64 + virgl (`ffsession.py --nofirefox --post`): from
  the root serial shell, `su leandro -c "XDG_RUNTIME_DIR=/run/user/1000
  WAYLAND_DISPLAY=wayland-1 firefox file:///tmp/tone.html"` and
  `sudo -u leandro env … firefox …`: 8 Firefox processes, all uid 1000/1000,
  WebAudio `state=running`; QEMU's captured audio shows two ~33 s blocks of a
  clean 440 Hz tone (RMS ~6948), one per launch.
- Same on x86_64 (TCG + virgl): 5-6 Firefox processes per launch, all uid
  1000, `state=running`, 76 s of tone captured (choppy: TCG starvation, as in
  lane/ffaudio). Firefox's "Failed to create EGLContext 0x3009" there is
  pre-existing: an in-session Firefox (ffsession baseline) logs the same.

## Notes / open

- `tty_nr` in /proc/<pid>/stat is still 0, so sudo's cache is per parent
  shell, not per tty session. Real `tty_nr` (pty major 136) is the follow-up.
- `/dev/tty` with no controlling terminal still proxies stdin (patch 3 works
  around it in sudo-rs only).
- `su leandro -c 'firefox … &'` (backgrounding *inside* su) was not tested;
  backgrounding the whole `su …` / `sudo …` from the caller's shell works.
- Without the new kernel the userland still works; only the 5 min credential
  cache is inert (old starttime changes every second).
