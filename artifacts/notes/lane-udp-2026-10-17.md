## What was fixed

1. **EPOLLET for UDP, ICMP and TCP listeners** (lane/sshspin left them level).
   smoltcp 0.11 has no UDP queue length, but with feature `async` every
   UDP/ICMP `process()` (datagram in) and `dispatch()` (datagram out) fires
   the socket's waker. Before each `Interface::poll` the daemon registers on
   every UDP/ICMP socket a waker whose data is the socket's position in the
   set (`readiness_sigs`, same order the snapshot uses; re-registering an
   equal waker is a compare, no allocation); it sets a bit in `RX_FIRED`,
   and `readiness_moved` turns each bit (or a readiness flip, as before)
   into a new `inet_seq` value plus a tag wake. Edges: one per datagram
   received (also behind an unread one — the case a readiness byte misses),
   one per datagram sent (what Linux does: sock_wfree -> sk_write_space;
   this is also what frees an EPOLLET writer that got EAGAIN on a queue
   with free slots but no payload room), and a can_send flip. Nothing fires
   while idle: no busy loop. POLLOUT is now `can_send()` (was always).
   Listeners: `listen::Listen::{seq, seen}` — `maintain_one` gives each
   queued connection that turns ESTABLISHED/CLOSE-WAIT one edge (survives
   the arm/queue slot swap); `handle_poll` reports the sum over stacks.
   Wildcard UDP servers report the sum of their sockets' seqs. Unbound UDP
   and unbound ping sockets report seq 0 (one EPOLLOUT edge). Kernel side
   needed no logic change (generic data[16] path), only its comment.
2. **Connected UDP**: only the peer's datagrams are seen (`udp_drop_foreign`
   at read/poll/FIONREAD; smoltcp filters by port only). `connect(AF_UNSPEC)`
   dissolves the association (keeps the port). `getsockname` after connect
   reports the route's source address (127.0.0.1 or the NIC's: the WebRTC /
   musl-sort "which local address" probe), unbound reports 0.0.0.0:0;
   `getpeername` with no peer is ENOTCONN for AF_INET sockets.
3. **udpany + connect (kernel panic)**: a 0.0.0.0:PORT server that connected
   to a peer on another stack removed its primary but `udpany::MIRRORS`
   still named it: next recv/poll panicked in smoltcp. Now
   `udpany::collapse` keeps the socket on the peer's stack and drops the
   rest (Linux: a connected socket hears only its peer).
4. **bind**: EADDRINUSE for a port held by another socket of the same
   protocol with an overlapping address (Linux inet_csk_bind_conflict /
   udp_lib_lport_inuse): allowed when both set SO_REUSEPORT (same euid) or
   both SO_REUSEADDR (TCP: not over a listener). Same description (dup,
   fork) never conflicts. A second bind() of a bound socket is EINVAL (it
   leaked the old smoltcp socket); bind() on a ping socket is accepted and
   ignored (it turned the socket into a UDP one).
5. **Smaller UDP gaps**: recv(MSG_TRUNC) answers the real length; a full
   send queue is EAGAIN (was ENOMEM — fatal to tokio/quinn), Unaddressable
   EINVAL; shutdown records directions (SHUT_RD: empty queue reads 0, poll
   POLLIN|POLLRDHUP; SHUT_WR: EPIPE; both: POLLHUP; waiters woken — the
   "unblock my recvfrom thread" pattern; unconnected: ENOTCONN as Linux);
   SO_BROADCAST and SO_REUSEPORT read back; SO_RCVBUF/SO_SNDBUF report the
   UDP buffers (512 KiB / 128 KiB) instead of TCP's.
6. **UDP GSO**: `setsockopt(SOL_UDP, UDP_SEGMENT)` always answered 0, which
   is quinn-udp's probe for GSO; it then hands sendmsg one buffer of up to
   64 packets with a UDP_SEGMENT cmsg, which went out as ONE oversized
   datagram. Now the cmsg or the option splits the send (`udp_send_gso`),
   EINVAL past 64 segments. Firefox 136's libxul links quinn-udp (it
   imports `recvmmsg`); whether HTTP/3 uses it or NSPR depends on
   `network.http.http3.use_nspr_for_io` — not measured here.
7. **sendmmsg/recvmmsg** (x86_64 307/299, aarch64 269/243) were ENOSYS: loops
   over sendmsg/recvmsg, MSG_WAITFORONE, timeout checked after each message
   as Linux does.

Already fixed before this lane (verified, dropped): dup of an inet socket
(`udp_dup` passes: lane fdgaps' shared-description model); UDP FIONREAD =
next datagram; zero-length datagrams; MSG_DONTWAIT/O_NONBLOCK EAGAIN.

## Refuted / not reproduced

- "QUIC bursts overflow smoltcp buffers": `udp_burst` 3000 x 1200 B
  nonblocking to an unread loopback socket: 3000 sent, 0 EAGAIN, 436
  received (the 512-slot rx ring; Linux in Docker kept 92) — drops are at
  the receiver as on Linux, never an error to the sender. The ENOMEM path
  is real (BufferFull) but did not trigger on loopback, where every kick
  drains the queue.
- "udpany: sockets bound before an interface appears": every NIC stack
  exists from `net::init` (netifs register before it), so mirrors cover
  every stack that will ever exist. A netif registered after init would have
  no stack at all — not a udpany problem.

## Open

- ECONNREFUSED on a connected UDP socket from an ICMP port unreachable:
  smoltcp delivers ICMP errors only to an ICMP socket bound to
  `Endpoint::Udp(port)` — one extra socket per connected UDP socket. Not
  cheap; SO_ERROR stays 0 for UDP.
- Multicast: IP_ADD_MEMBERSHIP is accepted and does nothing; smoltcp
  without `proto-igmp` drops multicast other than 224.0.0.1, so mDNS
  (224.0.0.251) is not received. Two sockets sharing a port (REUSEADDR/
  REUSEPORT) get unicast in smoltcp slot order (first match), not Linux's
  hash/load balancing, and broadcast/multicast only reaches the first.
- SO_BROADCAST is recorded, not enforced (Linux: EACCES without it).
- No IP fragmentation (`proto-ipv4-fragmentation` off): a datagram above
  the NIC MTU is dropped by smoltcp, a fragmented one never reassembled.
  Loopback (MTU 65535) is fine (`udp_large`).
- IP_PKTINFO / IP_RECVTOS / UDP_GRO: accepted, no cmsg produced (quinn-udp
  tolerates the absence).
- connect(AF_UNSPEC) keeps a port bind(0) picked (Linux releases it).
- Datagrams queued from an old peer are dropped at read after a re-connect
  (Linux keeps what was already queued).
- TCP connect(AF_UNSPEC) still goes down the AF_UNIX path (Linux aborts
  the connection).

## Merge risk

`servers/net/src/lib.rs` is touched in many places: readiness_sigs/
readiness_moved (daemon), handle_bind, handle_connect, handle_send(_k),
handle_sendmsg, handle_recv/recvmsg/udp_recv_k, shutdown, get/setsockopt,
handle_queue_len, handle_poll (inet arms), SockOpts. Lanes mediabus and
wifirx touching the daemon loop or `NicDevice` should merge textually;
anything else editing handle_poll's inet arms or handle_recv's UDP arm will
conflict. `listen.rs`, `udpany.rs`, `Cargo.toml` (smoltcp feature `async`)
small. `kernel/src/syscall.rs`: constants, dispatch arms, fd_handle_args /
not_a_socket lists, two new functions after sys_recvmsg.
