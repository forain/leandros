# lane/i8042 — 2026-10-23 — openbugs L8.6

Status: FIXED (a, b, c); (a) has no live-typing guard (see Open).

## Changes
- (a) Keyboard bytes during the AUX probe: `aux_read` and every probe-time flush
  (`kb::flush_keep_keys`, also before each command-byte read in `ctr_update`) now
  hold bytes whose status AUX bit (0x20) is clear in a 64-byte buffer
  (`kb::hold_key`, error-flagged bytes still dropped); `psmouse::init` replays them
  through `handle_scancode` once `AUX_BUSY` is cleared (success and failure paths)
  and logs `[PSMOUSE] keyboard bytes during the probe: N replayed, M lost` when nonzero.
- (b) MADT Interrupt Source Overrides: new `boot::acpi::for_each_madt_iso`;
  `ioapic::load_overrides` (called right after `ioapic::init`), `isa_route`,
  `set_isa_irq`, `mask_isa_irq` map ISA IRQ -> GSI with polarity (active low ->
  bit 13) and trigger (level -> bit 15). IRQ 1 (boot, `keyboard::recheck`, mask)
  and IRQ 12 now go through it. There was no override lookup before: every
  IOAPIC route was identity/edge/high.
- (c) Synaptics extended buttons: `SynInfo.ext_buttons` (ext caps 0x09 bits 12-15);
  `syn_xy` clears the low `(n+1)/2` bits of bytes 4/5 when (byte0^byte3) bit 1
  is set (Linux `synaptics_parse_ext_buttons`). PS/2 relative decoding was
  already correct (9-bit sign from byte 0, overflow drops the axis, buttons 0-2);
  now covered by the selftest.

## Guard
`drivers::psmouse::selftest()` + `ioapic::isa_redirection` checks run in every
x86 boot: `[PSMOUSE] selftest: ok` / `FAIL n`.
- Red on unfixed code: the decoder checks compiled on the host against the old
  `syn_xy` body give `selftest failures = 2`; fixed body `0`.
- x86_64 regress (TCG): overall PASS, boots failed 0/1; serial shows
  `[PSMOUSE] selftest: ok` and `[PSMOUSE] IRQ 12 -> GSI 12 -> vector 33`.
- aarch64 release build OK (driver is x86-only).
