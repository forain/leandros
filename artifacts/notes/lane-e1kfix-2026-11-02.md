# lane/e1kfix 2026-11-02: e1000e unload/reload safety (I219)

Static diagnosis, fixed without real-I219 verification.

- kmod unload now runs the module's own pm `shutdown` hooks (`pm_unload_quiesce`, kernel/src/kmod/sys.rs + exports/pm.rs) BEFORE `quiesce_pci`, while bus mastering is still on. Generic: any module with a pm shutdown hook gets an ordered stop.
- e1000e `shutdown()`: IMC, RX off, descriptor-ring flush (SPT+), TX off, IMC, DRV_LOAD release. Module exit no longer repeats it (bus master already off then); new `unload_keep_drv_load()` re-sets DRV_LOAD so the ME is not handed a MAC that is about to be re-initialised. Reboot path (kernel pm2) unchanged semantically (still releases DRV_LOAD), now also flushes.
- Ring flush is now `FlushCtx::flush`; if FLUSH_DESC_REQUIRED is set and TDLEN==0 or TDBA is not our ring (state from a previous generation), TDBA/TDLEN are first pointed at the new TX ring (one log line) instead of skipping. bring_up runs it ("pre_flush" step) before the first reset_hw.
- Driver thread: `should_stop` checked between bring_up steps, after bring_up, in the SWFLAG waits and in the ULP wait, so the 5 s lower drain no longer times out into a zombie.
- Same-name zombie already refused by load.rs (KmodErr::SlotBusy); no change.
- Test: scripts/kmod/e1000etest.sh now takes an arch arg (aarch64 works) and checks carrier-up after each of 10 reloads.
- Untestable in QEMU: I219 (PCH) paths: FLUSH_DESC_REQUIRED, DESC_RING_STATUS 0xe4, SWFLAG/ULP timing, ME DRV_LOAD handover. QEMU only has the 82574L.

## Review fixes (lane/e1kfix2)
- Gate `stopping` is set BEFORE the unload hook (sys.rs), so the driver thread sees should_stop first.
- New `unload_quiesce` op appended to KPmOps (all other drivers pass None; reboot `shutdown` hooks no longer run at rmmod). e1000e registers via register2 (NET phase).
- e1000e `unload_quiesce()`: RUNNING=false, bounded (3 s) wait for new THREAD_DONE flag, then quiesce with a bounded blocking RINGS lock (reboot keeps try_lock) and DRV_LOAD left alone; `unload_keep_drv_load()` removed.
- Stale-state flush now clears TCTL.EN before rewriting TDBA/TDLEN/TDH/TDT.
- Tests aarch64: e1000etest all ok, unload hook fired 10/10; check-rpi5.sh rc 0. I219 paths still unverified.
