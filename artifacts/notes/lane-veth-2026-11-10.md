# lane/veth: veth pairs across network namespaces (L1 of design-podnet3) - FIXED

## What landed
- servers/net/src/framedev.rs: the smoltcp Ethernet frame device (was `TapDev` in tunbe.rs), shared by tap, tun and veth ends.
- vifsel/vif: `VifKind::Veth`, `Vif.peer` (the other end's sid, any netns), `MAX_NS0_SIDS` (24) for netns 0, `vif::free_vifs`;
  `reap` of a dead netns also frees the peers living in other namespaces.
- tunbe.rs: `veth_create` (RTM_NEWLINK kind=veth, VETH_INFO_PEER, IFLA_NET_NS_FD / IFLA_NET_NS_PID via `vfs::nsfd_target`,
  `veth%d` naming in each namespace, CAP_NET_ADMIN checked in both namespaces), `veth_delete` (RTM_DELLINK removes both ends),
  `poll_all` hands a veth end's frames to the peer's rxq (peer must be admin up and MTU fits).
- rtnetlink.rs: `create_link` (nested LINKINFO/INFO_DATA/VETH_INFO_PEER parsing), RTM_DELLINK, GETLINK reports kind "veth" + IFLA_LINK.
- iface.rs: netns-0 `route_select` consults dynamic connected/explicit routes before the NIC default route.
- lib.rs: a wildcard UDP bind in a netns with no peer picks the netns's first interface stack (was ENETUNREACH; found by brtest).
- nlsock.rs: `vif::daemon_pass()` before each request so pairs of dead namespaces are reaped on the next netlink call.
- userland/brtest/brtest.c (registered in build-userland.sh, mkfs-f2fs-populated.py, runtests.py regress list and suite `bridge`):
  veth_pair (UDP + TCP echo over the pair), veth_ping (ICMP both ways), veth_dellink, veth_naming, veth_nsgone (200x).

## Evidence
- Fail-first on the box (aarch64, baseline = test only, e52d6455): RTM_NEWLINK kind=veth fails, so veth_pair, addr, up, ... FAIL, run times out.
- After: brtest passes on aarch64 (HVF), see merge commit.

## Not done / open
- IFLA_NET_NS_* on an existing link (SETLINK move) is not implemented; only create-with-peer-in-ns.
- IFLA_MASTER is ignored (bridge is lane L2).
- A veth end's stack is freed without waiting for sockets bound on it (same as tap detach).
- OPEN: a netns that ran a TCP flow (child listener + accepted conn) was still not reaped 20 s after the child exited (vethA stayed), while UDP/ICMP/no-socket
  namespaces are reaped within one request (veth_nsgone 200x). Something in the TCP path (TIME_WAIT/orphan entry) pins the netns reference; to look at in fwdtcp/podbridge (`--rm` containers).
