## L6.6 'LEANDRO2026' not joinable — cause: WPA/WPA2 mixed mode (TKIP group cipher)
klog: `RSN v1 group TKIP pairwise TKIP,CCMP akm PSK caps 0x0000 (MFPC 0 MFPR 0) +WPA1 element`
(14:23:33:fa:5b:e8, ch 8, -53 dBm, HT VHT). LEANDRO20265G (14:23:33:fa:5b:f0, ch 149-157) is the same.
It is neither PMF nor SAE: AKM is plain PSK and MFP is off. select_akm requires a CCMP group
(drivers/src/wifi_mgr.rs:307), and the driver has no TKIP at all.
- Fastest fix, on the router: set WPA2-AES (CCMP) only. The scan log already says so.
- Driver fix (not done, ~1.5-2 days): group-TKIP RX only, since a STA never sends with the GTK.
  Echo group TKIP in the assoc RSN IE (iwl_assoc.rs); keep pairwise CCMP (EAPOL descriptor v2);
  accept a 32-byte GTK KDE; then either install it as a firmware TKIP key (ADD_STA_KEY TKIP flags plus
  phase-1 TTAK, firmware decrypts, host checks Michael MIC) or decrypt in software (TKIP mixing + RC4 +
  ICV + Michael + TSC replay, ~400 LOC). Host tests: 802.11 Annex M TKIP/Michael vectors, plus a
  wifi_sim mixed-mode join (today's `bss-tkip-group-not-joinable` and `connect-tkip-unsupported` then
  flip). Broadcast RX (ARP/DHCP) depends on it, so a partial job is useless.
- There is no saved profile for LEANDRO2026 (`netctl profiles`: only "Anvara 5G" and legacy "Anvara"),
  so a join can't be tested on hardware even after a fix.
- Fast-Boot-ON "no networks" (code reading only): nothing found that resets the NIC from an unknown
  firmware state. Needs a human BIOS toggle plus a klog capture of the scan path (scan cmd status,
  channel count, `last scan` age in /proc/net/wifi) on that boot.

## Found in passing
- `netctl connect Anvara --bssid X` (no secret) gave `unsupported-security`, while `--uuid` of the same
  profile worked. On a trial cmdline without the legacy wifi.ssid= args, the profile doesn't exist and
  the name falls through to an inline open connect. That is expected, but the error is misleading. With
  args present it still failed once, possibly the remote shell's quoting. Unverified.
- The good entry's cmdline still carries the legacy wifi PSK (`wifi.psk=`), so it can be read from
  /proc/cmdline by any user. Promoting with a plain `iwlwifi.mgr=1` cmdline removes it (the 5G profile
  holds its own secret), but that also drops the legacy 2.4 GHz "Anvara" profile.
