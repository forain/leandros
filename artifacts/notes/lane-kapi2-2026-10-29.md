## Done
- exports.rs split into kernel/src/kmod/exports/{mod,core_,pci,irq,net,pm,v4l2,usbfn,common}.rs (pure move first commit). The
  submodule for USB function handles is `usbfn` because a module named `usb` shadows the usb crate. Shared imports live in mod.rs.
- B1: `RegKind::TICK`/`PM` records; `registry::release_all(owner)` runs on failed init (load.rs) and unregisters tick, pm and
  v4l2 before the slot is freed. irq/netdev/hwrng/kthread/usb_class have no unregister path: their record stays and the slot is
  leaked (as before, safe). `usb::class::tick_unregister_owner` waits for in-flight `tick()` on other CPUs.
- pm hooks are a list (`kapi_pm_register` no longer returns -16); new `kapi_pm_register2` + `KPmOps` + `pm_phase::*`.
- M2: `kernel/src/pm2.rs` owns all ordering (suspend INPUT,GPU,NET,WIFI,BLOCK,USB,PCI; shutdown SOUND,NET,WIFI; block shutdown;
  kexec CONSOLE,BLOCK,GPU,NET,WIFI). pm.rs `DEVS` and the hard-coded calls in power.rs (`shutdown_all`, `quiesce_phase1`,
  `kexec_hooks`) now call pm2. A driver that becomes a module only edits its row in `pm2::BUILTIN`.
- Added exports: kapi_pm_register2, kapi_virt_to_phys (u64::MAX outside the HHDM, so module-window addresses are refused),
  kapi_can_sleep, kapi_sleep_until, kapi_yield, kapi_irqs_masked, kapi_current_pid (NEXPORTS 51). kmod-abi/kmod-kapi updated.
- Pre-created drv-nvme, drv-virtio-blk, drv-usb-storage, drv-usb-hid, drv-virtio-snd, drv-virtio-keyboard, drv-bt,
  drv-hdmi-audio in kernel/Cargo.toml (empty features; the Kconfig symbols already existed, default y, bool) and every later
  SLOTS line (next free 304).
- USB autoload hook and autoload_aliases honour kmod=0. modules.load keeps boot order (nothing sorts it).
- ktest kmodkapi: new `kmodkapi_w2` (failed init of tick, pm, v4l2; non-releasable kinds stay recorded; virt_to_phys; pm2 order);
  the old pm hook case was rewritten for the list semantics.
- Evidence: aarch64 release build ok, scripts/kmod/selftest.sh all PASS.
