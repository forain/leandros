# Networking

[`servers/net`](../../servers/net) provides two largely separate socket families behind one fd range: **AF_INET** — TCP, UDP and ICMP over virtio-net or a real Realtek NIC through [smoltcp](https://github.com/smoltcp-rs/smoltcp), with a DHCPv4 client and a separate loopback interface — and **AF_UNIX**, implemented in full because every Wayland and D-Bus connection in the system rides on it. Both are driven by Linux syscalls with Linux semantics; the reference for every behaviour below is what Linux's own `net/` code does.

## Overview

| Piece | Summary |
|---|---|
| Socket tables | one `ProcSockTable` per process, heap-allocated on first use and reused; its slots are a growable vector. Slot `i` is handle `SOCK_FD_BASE + i` (`0x0100_0000 + i`), which a process reaches only through a `SockAlias` entry of its fd table — every socket is an ordinary descriptor at the lowest free number |
| AF_INET | one smoltcp `Interface` + `SocketSet` per network interface (`STACKS[sid]`: loopback 127.0.0.0/8 at `LO`, then one per netif of `drivers::netdev`'s registry) |
| DHCP | one DHCPv4 client per netif; `/etc/resolv.conf` (`# from DHCP`) lists every lease's DNS servers, the default route's first |
| AF_UNIX | connection pool of 512 (`UNIX_CONNS`), bound-address pool of 512 (`BOUND_PATHS`), growable per-direction rings 4 KiB → 208 KiB |
| Pathname sockets | `S_IFSOCK` nodes on tmpfs only ([vfs.md](vfs.md#tmpfs)) |
| `/proc/net/*` | Linux-format `route` (per interface, real metrics, preferred first), `dev`, `tcp`, `udp`, `unix`, plus `tcpsnd`, `listen` (below) and `tcp6`, `udp6`, `raw`, `raw6` ([`procnet.rs`](../../servers/net/src/procnet.rs)); LeandrOS `nic` (one `[ifname]` section per interface) and `wifi` |
| Daemon | `net_daemon` sleeps until smoltcp's next timer (microsecond stack clock), runs at 1 kHz while frames flow and 100 Hz when idle, and is woken by `netdev::kick()` on sends, window reopening and the r8169 RX interrupt |
| Interfaces | every device is its own interface ([`netdev.rs`](../../drivers/src/netdev.rs)): wired NICs in probe order (virtio-net, Realtek r8169 — [pc.md](../hardware/pc.md#ethernet-realtek-r8169) — Intel e1000e, Amazon ENA on EC2) are `eth0`, `eth1`, ...; Intel Wi-Fi is `wifi0`. Metric: wired 100 (+n), Wi-Fi 600, overridable per interface (`net.metric.<if>=` boot knob, `netctl metric`; see [netctl.md](netctl.md)). DHCP restarts on link up |
| TCP buffers | 2 MiB receive window (window scaling), 256 KiB send buffer (smaller past 48 sockets, fallible allocation); UDP 512-slot receive ring, 512 KiB receive / 128 KiB send buffers (what `SO_RCVBUF`/`SO_SNDBUF` report) |
| smoltcp | 0.11.0, vendored in [`servers/net/vendor/smoltcp`](../../servers/net/vendor/smoltcp) with a TCP loss-recovery patch, Reno/CUBIC congestion control and a UDP head-of-queue timeout ([LEANDROS-PATCH.md](../../servers/net/vendor/smoltcp/LEANDROS-PATCH.md)) |

Host↔VM networking works in both directions on every accelerator; `ping` is in the userland, and `nettest` is part of the `regress` suite.

## TCP/IP

### How it works

- **One interface, one socket set.** Every network interface — loopback, each NIC, Wi-Fi — is its own smoltcp `Interface` with its own `SocketSet`, never a second address on a shared one. Two interfaces sharing one set would let whichever polls first claim a socket's pending segment, so a loopback SYN could be emitted onto the wire and never delivered (or a flow routed through one NIC leave through another). Separate sets make the choice explicitly, once, at `bind`/`connect` time. The loopback stack is unconditional — it exists even with no NIC — and a NIC's stack exists from boot whether or not it has an address yet.
- **Routing** ([`iface.rs`](../../servers/net/src/iface.rs)). A new flow (TCP `connect`, the first `sendto` of a UDP or ping socket) goes to `lo` for 127/8; else to the interface whose on-link subnet holds the destination (longest prefix, then lower metric); else to the lowest-metric interface with a default route. Only interfaces with an address and carrier count. A socket bound to an address lives on the interface holding it. Established flows stay pinned to their interface; a UDP socket not bound to an address moves (same port) when its interface can no longer reach the destination.
- **Address lifetime.** A lease installs the address and a default route. Losing the lease (or the carrier for more than 4 s) removes both and resets every TCP connection on that interface, so failover to the next interface is immediate for new flows. A carrier loss shorter than that, or a link that comes back with the same lease (kept for up to 10 s while DHCP re-runs), keeps established connections. Only QEMU's first virtio-net starts with the slirp pre-lease address 10.0.2.15/24.
- **Binding.** Port 0 is assigned at `bind` (not at `listen`), which is what makes `bind("127.0.0.1:0")` — every mio/tokio `TcpListener::bind` — work. Ports below 1024 require root (`EACCES`).
- **Listeners** ([`listen.rs`](../../servers/net/src/listen.rs)). smoltcp has no accept queue — a LISTEN socket takes the first SYN and *becomes* that connection — so a listener is, on every stack it listens on, a LISTEN socket plus an accept queue held by that stack: after each daemon poll the socket that took a SYN joins the queue and a fresh LISTEN socket is armed (up to 16 pending per stack), a handshake that does not complete in 60 s is aborted, a connection reset before `accept` is dropped, and anything that kills the LISTEN socket (an address loss resetting the stack's connections) is repaired on the next pass. `accept` takes the oldest ESTABLISHED or CLOSE-WAIT connection, and `poll` reports both. The LISTEN socket is kept at a higher socket slot than its queue (smoltcp gives a segment to the first socket that accepts it), so a retransmitted SYN reaches its own handshake instead of starting a second one. A wildcard listener is on every stack, a 127/8 one on loopback, any other address on every NIC stack with that address as filter, so listeners follow every lease, address change and roam untouched. Until lane netroam there was one socket per stack per listener: every SYN got an RST while it was busy, and a connection the client gave up on before `accept` (CLOSE-WAIT, which `poll` did not report) or a handshake to a vanished peer left the port refusing for good — sshd on the laptop's wifi0 after Wi-Fi roaming.
- **UDP servers** ([`udpany.rs`](../../servers/net/src/udpany.rs)). A UDP socket bound to INADDR_ANY with a chosen port gets a socket on every stack (keyed by its open file description): `recv`/`poll`/`FIONREAD` look at all of them, a reply leaves from the stack its destination routes through. Port-0 binds, connected sockets and address binds stay on one stack (until lane netroam a wildcard server lived on the default route's interface only).
- **TIME_WAIT.** A closed connection's port is reserved for 60 s (Linux's fixed `TCP_TIMEWAIT_LEN`): an explicit `bind` to it is `EADDRINUSE` unless `SO_REUSEADDR` is set, and automatic ports skip it. Only the *port reservation* is modelled — the smoltcp socket is still torn down at close, so nothing lingers to re-ACK a retransmitted FIN. Under pressure (64 reservation slots) the newest reservation is simply not recorded, so the failure mode is the old instant reuse, never an unsatisfiable `bind`.
- **Options.** `TCP_NODELAY`, `SO_KEEPALIVE`, `TCP_KEEPIDLE`/`KEEPINTVL`/`KEEPCNT` take effect (defaults 0/7200/75/9, Linux's ranges and `EINVAL`s). They live in a side map keyed by **open file description**, applied at `connect`, at `accept` (an accepted socket inherits them from its listener, as Linux's `sk_clone_lock` does), on `setsockopt` of a connected socket, and when the handshake completes. The TCP level on a non-TCP socket answers like Linux: `EOPNOTSUPP` for AF_UNIX, `ENOPROTOOPT` for UDP/ICMP/raw.
- **Peeking.** `MSG_PEEK` leaves data queued on TCP (`peek_slice`) and UDP (`peek`), for `recv`, `recvfrom` and `recvmsg`.
- **Half-close.** `shutdown(SHUT_WR)` delivers EOF to the peer while the reply still arrives; `send` after it is `EPIPE`; `shutdown` of a listener or an unconnected socket is `ENOTCONN`.
- **Address conflicts.** `bind` is `EADDRINUSE` for a port held by another socket of the same protocol with an overlapping address (Linux's `inet_csk_bind_conflict`/`udp_lib_lport_inuse`), unless both set `SO_REUSEPORT` (same euid) or both set `SO_REUSEADDR` (for TCP, not over a listener). Copies of one description (`dup`, fork) never conflict. A second `bind` of a bound socket is `EINVAL`; `bind` on a ping socket is accepted and ignored.

### UDP

- **Demultiplexing** (the patched smoltcp `process_udp`, see [`vendor/smoltcp/LEANDROS-PATCH.md`](../../servers/net/vendor/smoltcp/LEANDROS-PATCH.md)). Broadcast and multicast reach *every* socket bound to the port (one sharing it with `SO_REUSEADDR`/`SO_REUSEPORT` included); a socket bound to a unicast address hears neither, as on Linux. Unicast goes to the best match (bound address, then connected peer), the most recently bound on a tie (Linux's hash-chain order), and within a `SO_REUSEPORT` group to the socket a hash of the flow picks.
- **Connected UDP.** After `connect`, only the peer's datagrams are accepted (`udp::Socket::set_peer`, at demultiplexing time), so datagrams queued before a re-connect stay readable, as on Linux. `connect(AF_UNSPEC)` dissolves the association; a port nobody chose (bind port 0, or picked by `connect`/the first send; Linux's `SOCK_BINDPORT_LOCK`) is given up — `getsockname` says port 0, the next send or connect binds a new one, `bind` is allowed again — while queued datagrams stay. A connect to a broadcast address needs `SO_BROADCAST` (`EACCES`).
- **ICMP errors.** A connected socket gets the fatal ICMP errors about its datagrams (port/protocol unreachable, prohibited, ...: Linux's `icmp_err_convert`) as a pending error: the next `recv`/`recvmsg` or `send` fails with it once (`ECONNREFUSED` for a closed port), `poll` reports `POLLERR`, `SO_ERROR` reads and clears it. Unconnected sockets never see one unless `IP_RECVERR` / `IPV6_RECVERR` is on: then every ICMP error about a flow of the socket (also non-fatal ones, frag-needed with `EMSGSIZE`, and ICMPv6 packet-too-big) is queued on the socket error queue and arms the pending error. `recvmsg(MSG_ERRQUEUE)` (`MSG_PEEK` supported) returns the quoted payload, the failed destination in `msg_name` and an `IP_RECVERR`/`IPV6_RECVERR` cmsg holding `struct sock_extended_err` (`SO_EE_ORIGIN_ICMP`/`ICMP6`/`LOCAL`, `ee_type`, `ee_code`, `ee_info` = MTU) followed by the ICMP sender's sockaddr (`linux/errqueue.h`); `poll` reports `POLLERR` while the queue is non-empty. A DF datagram larger than the path MTU (`IP_PMTUDISC_DO`/`PROBE`) fails with `EMSGSIZE` and, with `IP_RECVERR`, leaves a local entry carrying the MTU. `IP_PMTUDISC_DONT` and `WANT` datagrams leave with DF clear, `DO`/`PROBE` with DF set (checked on the wire by `peer_df`). Over loopback the error comes from the loopback stack's own port-unreachable. `getsockname` after `connect` reports the route's source address — the "which local address would I use" probe that WebRTC and musl's address sorting make — and an unbound socket reports `0.0.0.0:0`; `getpeername` with no peer is `ENOTCONN`. A wildcard server that connects to a peer on another stack collapses onto that stack (`udpany::collapse`).
- **Receiving.** `recv(MSG_TRUNC)` returns the datagram's real length; `FIONREAD` is the next datagram's size; zero-length datagrams work; `MSG_PEEK` as above. `recvmsg` adds Linux's control messages: `IP_PKTINFO` (`ipi_ifindex` = stack id + 1, `ipi_addr` the destination, `ipi_spec_dst` the destination or, for broadcast and multicast, the interface's address), `IP_TTL` (`IP_RECVTTL`), `IP_TOS` (`IP_RECVTOS`, one byte) and `UDP_GRO`; whole messages that fit, `MSG_CTRUNC` for the rest. With `UDP_GRO` on, consecutive datagrams from one source of the first one's size (the last may be shorter) come back in one buffer, up to 64, with the size in the cmsg — what Linux's GRO gives such a socket, and what a `UDP_SEGMENT` send over loopback looks like to it.
- **Sending.** A full send queue is `EAGAIN` (it was `ENOMEM`, fatal to tokio and quinn); an unaddressable destination is `EINVAL`. Bursts to an unread socket drop at the receiver, never as an error to the sender, as on Linux.
- **`shutdown`** records directions: after `SHUT_RD` an empty queue reads 0 and polls `POLLIN|POLLRDHUP`, `SHUT_WR` makes `send` `EPIPE`, both give `POLLHUP`, and blocked readers are woken — the "unblock my receiving thread" pattern. On an unconnected socket it is `ENOTCONN`, as Linux.
- **GSO.** `setsockopt(SOL_UDP, UDP_SEGMENT)` and a `UDP_SEGMENT` cmsg split one `sendmsg` buffer into datagrams of the given size (up to 64 segments, else `EINVAL`). quinn-udp probes for exactly this; before, the probe said yes and the whole buffer left as one oversized datagram.
- **`SO_RCVTIMEO` / `SO_SNDTIMEO`** (lane sotimeo) bound every blocking wait the kernel does for a socket — `recv*`/`read`, `send*`/`write`/splice output, `accept` (receive timeout) and a TCP `connect` (send timeout) — on TCP, UDP and AF_UNIX sockets, as Linux's `sock_rcvtimeo`/`sock_sndtimeo`: `EAGAIN` when the time runs out (a TCP connect: `EINPROGRESS`, the handshake carries on), `{0,0}` is no timeout, a negative `tv_sec` is "do not wait", `tv_usec` outside `[0, 1e6)` is `EDOM`, a short struct `EINVAL`, and `getsockopt` reads the value back. A signal ends a wait with a timeout set as `EINTR` even under `SA_RESTART`; one without a timeout is restarted. Both live in `SockOpts` (per open file description; an accepted TCP socket inherits the listener's, an accepted AF_UNIX one starts without, as on Linux) and the kernel reads them through `net_server::sock_timeo` only after a first `EAGAIN`. They were accepted and ignored until then, so a blocking recv with a timeout waited forever.
- **Blocking `accept`** waits for a connection (bounded by `SO_RCVTIMEO`; `SA_RESTART` restarts it). It used to answer `EAGAIN` at once, like a non-blocking listener.
- **Two SYNs for one listener in one poll** are both accepted. A listener has one LISTEN socket per stack, re-armed between polls, and smoltcp takes every queued frame in one poll, so the second SYN found no LISTEN socket and got an RST — every pair of back-to-back loopback connects. The daemon now polls each stack through `syngate::SynGate`, which hands smoltcp one pure SYN per poll, holds the next, and re-polls after `listen::maintain` has re-armed (at most 64 re-polls per pass; a SYN still held then is dropped, which the peer retransmits).
- **`sendmmsg`/`recvmmsg`** loop over `sendmsg`/`recvmsg`, with `MSG_WAITFORONE` and the timeout checked after each message, as Linux does.
- **Broadcast.** Sending to (or connecting to) `255.255.255.255`, `127.255.255.255` or an interface's directed broadcast without `SO_BROADCAST` is `EACCES` (Linux's route-lookup check). This host gets a copy of its own broadcast (Linux `ip_mc_output`): the send path builds the frame the NIC would carry and queues it to the interface's own receive side (`INJECT`), so the normal demultiplexing delivers it.
- **Path MTU discovery.** An ICMP "fragmentation needed" (and ICMPv6 "packet too big") teaches a per-network-namespace cache (600 s expiry, floors 552 / 1280, a lower report always lowers the entry). `IP_MTU_DISCOVER` / `IPV6_MTU_DISCOVER` (default `WANT`; `DONT` ignores the path, `DO`/`PROBE` fail an oversized send with `EMSGSIZE`), `IP_MTU` / `IPV6_MTU` (connected sockets; `ENOTCONN` otherwise; a namespace's own loopback reports 65536) and `TCP_INFO` `pmtu`/`snd_mss` read the cache, and TCP segments and IPv4 fragmentation follow it ([`pmtu.rs`](../../servers/net/vendor/smoltcp/src/pmtu.rs)).
- **Multicast.** `IP_ADD_MEMBERSHIP`/`IP_DROP_MEMBERSHIP` (`ip_mreq` or `ip_mreqn`; interface by index, address, else the group's route) are per socket ([`mcast.rs`](../../servers/net/src/mcast.rs)); the interface is a member while any socket is, and smoltcp (`proto-igmp`) sends the IGMPv2 report on the first join and the leave after the last (`EADDRINUSE` for a repeated join, `EADDRNOTAVAIL` for leaving a group not joined, `EINVAL` for a non-multicast group, at most 20 per socket). As with Linux's default `IP_MULTICAST_ALL`, every socket bound to the port hears a group the interface joined — this is how mDNS on 224.0.0.251:5353 is received. `IP_MULTICAST_TTL` (default 1, 0 = host only), `IP_MULTICAST_LOOP` (default on: the local copy as for broadcast), `IP_MULTICAST_IF` (address or `ip_mreqn`; also used for `255.255.255.255`) work and read back. `/proc/net/igmp` lists each interface's groups in Linux's format.
- **IP options.** `IP_TOS` and `IP_TTL` set the TOS byte and TTL of each datagram sent (also on fragments) and read back.
- **Fragmentation.** A datagram larger than the NIC's IP MTU (1500) leaves as IPv4 fragments (payload a multiple of 8, all in one daemon pass); incoming fragments are reassembled (16 datagrams in flight per interface, 30 s timeout like `ipfrag_time`, a datagram ending past 65535 bytes or with a bad fragment dropped whole). The NIC's smoltcp MTU was 1500 *including* the Ethernet header (IP MTU 1486) until lane udp2; it is now 1514.
- `SO_BROADCAST` and `SO_REUSEPORT` read back what was set.

### Local delivery and UDP head-of-line blocking

smoltcp never delivers a packet addressed to the host's own IP: it ARPs for it, nobody answers, and the datagram waits in the socket's TX queue. Firefox's ICE/STUN code, which sends to its own interface addresses, hit exactly that, and the stuck datagram also blocked a later STUN request to a real server on the same socket (lane udpself). Two changes:

- `local_delivery()` in [`lib.rs`](../../servers/net/src/lib.rs) runs from `TxToken::consume` after the Output nftables hook. An ARP request for an address a local netif holds is answered inside the stack; an IPv4 frame whose destination MAC belongs to a local netif is queued to that netif's stack instead of being transmitted. It works across interfaces (an `eth0` socket to the `wifi0` address) and for connected, unconnected and wildcard-bound senders.
- The vendored `udp.rs` drops a head datagram that cannot be dispatched for 3 s (`TX_STALL_MS`, about what Linux does on an unresolved neighbour). Later sends to other destinations still wait behind it within those 3 s, which Linux does not do. A TCP SYN to an unresolvable host sits in its own socket and blocks nothing.

`userland/udpselftest` (in `regress`) covers own-IP send and reply, wildcard and connected senders, and a dead on-link host followed by a DNS query from the same socket.

### TCP congestion control

The stock smoltcp 0.11 sender had no congestion window: each burst was the whole 256 KiB send buffer. On the Pi 5's real `eth0` that overran the bridge and stalled bulk sends (0.28 MB/s with 13 MB in 48 s). The vendored `tcp.rs` now has Reno and CUBIC (`Cc`); the sender window is `min(peer window, cwnd)`. Default is **CUBIC**; measured Pi to Mac over ssh, 20 MB: none 0.28-0.58 MB/s, Reno 21-27, CUBIC 28.6-29.4 MB/s; `wifi0` stays near 1.5 MB/s (air and cipher limited, not congestion). Review fixes (lane pitcp2): growth only when cwnd-limited, cwnd clamped to max(peer window, send buffer), integer-only CUBIC (`icbrt` once per epoch, no floating point in the datapath), ssthresh/`w_max` kept across repeated RTOs, a Reno-friendly estimate, restart at the initial window after an idle longer than the RTO, and RFC 6582 `rto_recover`.

Knobs (kernel command line, read once by netd): `tcp.cc=none|reno|cubic` (unknown value logs a warning and uses cubic; `none` restores the old unlimited behaviour), `tcp.iw`, `tcp.rto_min_ms`, `tcp.sndbuf_kb`, `net.cadence_us`. `/proc/net/tcpsnd` has one line per sending TCP socket (flight, cwnd, ssthresh, counters), and `/proc/net/nic` ends with `netd_pass_hist:` (frames sent and received per daemon pass). Not done: fast-recovery inflation and fast convergence.

### Late-built stacks

A Wi-Fi netif whose MAC is known late (Pi 5 `wifi0`, after the brcmf firmware reports it) gets its smoltcp stack from the daemon seconds into boot. Listeners and UDP servers created earlier existed only on the stacks present then, so sshd on `0.0.0.0:22` had no LISTEN socket on `wifi0` and every SYN got an RST while ping worked. [`latestack.rs`](../../servers/net/src/latestack.rs) keeps a registry; when `init_nic` stores a new stack it calls `listen::adopt` and `udpany::adopt`, which add the missing sockets (`[NET] wifi0: adopted N listener(s), M udp server(s)`), idempotently and safe against a close racing the adoption. `/proc/net/listen` shows each listener per stack and which registered ones are missing a stack. An unresolved case: after sshd is killed and restarted on the Pi, one probe timed out rather than being refused.

### Netlink and interface ioctls

`socket(AF_NETLINK, SOCK_RAW|SOCK_DGRAM, NETLINK_ROUTE)` exists, minimal, because Firefox's nICEr (and any `getifaddrs`) found no local addresses and so produced no ICE candidates ([`rtnetlink.rs`](../../servers/net/src/rtnetlink.rs) encodes the messages, [`nlsock.rs`](../../servers/net/src/nlsock.rs) is the socket plumbing with a queue per open file description). Other netlink protocols are `EPROTONOSUPPORT`.

- `RTM_GETLINK` dump (name, address, broadcast, MTU, operstate), `RTM_GETADDR` dump (IPv4 only), `NLMSG_DONE` as its own datagram, datagrams at most 3.5 KiB. Dumps need `NLM_F_DUMP`; a non-dump `RTM_GETROUTE` gets a single `NEWROUTE`; the `RTM_GETROUTE` dump is empty and a `GETNEIGH` dump answers `DONE`. Any other request is `NLMSG_ERROR(EOPNOTSUPP)`.
- `recv` supports `MSG_PEEK` and `MSG_TRUNC`. An empty blocking `recv` returns `EAGAIN` (clients send first).
- The socket ioctls `SIOCGIFNAME/CONF/FLAGS/ADDR/BRDADDR/NETMASK/MTU/HWADDR/INDEX` work on any socket fd ([`syscall.rs`](../../kernel/src/syscall.rs)); `SIOCETHTOOL` and `SIOCGIWRATE` are `EOPNOTSUPP`, an unknown name `ENODEV`.
- Ifindexes: `lo` is 1 (synthesised), netifs are id + 2. `wifi0` has an address only when configured.
- `userland/netlinktest` (in `regress`) covers `getifaddrs`, `if_nameindex` and `SIOCGIFCONF`.

### Readiness edges

`EPOLLET` works on every inet socket (see [../kernel/event-loop.md](../kernel/event-loop.md#epoll-semantics)). The net daemon snapshots each socket's readiness — and, for TCP, its receive and send queue lengths — before and after each `Interface::poll`; any difference is an edge, which gets a fresh value from a global sequence (`NetStack::inet_seq`) and a keyed wake of that socket (`inet_key`, at most 16 per pass, else a bit-only wake). UDP and ICMP sockets register a smoltcp waker that fires on every datagram received or sent, so a second datagram behind an unread one is an edge too, and `POLLOUT` follows `can_send()`. Listeners (`listen::Listen::{seq, seen}`) give one edge per queued connection that becomes established. Nothing fires while a socket is idle. Before lane sshspin only AF_UNIX sockets had edges, and an idle SSH session kept tokio's sshd reactor at 100 % of a CPU on the permanently writable TCP socket.

### TCP loss recovery

smoltcp 0.11 recovered from a loss go-back-N: a fast retransmit rewound to `SND.UNA` and resent the whole window, ACKs of new data did not restart the retransmission timer, the RTO floor was 10 ms, and a window-update ACK reset the duplicate-ACK count (so a peer that autotunes its receive buffer never reached three). On a Wi-Fi-like link with 1 % loss that put 46 % extra bytes on the wire and cost 43 % of the upload throughput. The vendored copy fixes all four: RFC 6298 §5.3 timer restart, a 200 ms RTO floor, one-segment fast retransmit with NewReno partial-ACK retransmits (recovery point fixed at entry), and window updates that neither count nor reset the run. A retransmit is committed only once the device accepted the frame. `/proc/net/nic` shows the counters (`tcp_recovery:`). There is no congestion control beyond what the driver's TX backpressure bounds (smoltcp 0.12 has Reno/CUBIC).

### netshape link emulator

`netshape=<if>:<tx_kbit>:<rx_kbit>[:<txq>[:<rxq>[:<delay_ms>[:<loss_permille>]]]]` on the kernel command line ([`drivers/src/netshape.rs`](../../drivers/src/netshape.rs)) puts a slow queued link between the net server and one netif, the shape of a Wi-Fi association: a FIFO each way at the given rate, TX held at `txq` frames (default 64, iwlwifi's backpressure), an RX queue of `rxq` frames with tail drop (default 256, an AP's queue), a one-way delay (default 2 ms) and random loss in per mille. A rate of 0 leaves that direction unshaped. `/proc/net/nic` shows its counters (`shape:`). It is a test knob, off by default; for example `netshape=eth0:8000:8000:64:256:2:10` is 8 Mbit/s with 1 % loss.

### Shared sockets

An inet (or ICMP) socket's object is a set of smoltcp handles named by value from its `SockState`; unlike an AF_UNIX end it has no refcount of its own. Every holder — the creator, a `dup`, a fork child, an `SCM_RIGHTS` receiver, a `pidfd_getfd` caller — keeps its own copy of the entry, and what ties the copies together is the **open file description** they share (`SockEntry::ofd`):

- **The description's refcount is the socket's.** The holder whose put drops it to zero tears the handles down (`inet_put`, counted under `SOCK_TABLES` so that last holder sees what the others published). A socket that got no description (the table was full) is never shared: fork, `dup` and `SCM_RIGHTS` refuse it.
- **State changes reach every copy.** `bind`, `listen`, `connect` and its outcome, `accept` re-arming the listener, `SO_REUSEADDR` and an ICMP socket's first send are copied into every table entry of the description and into a canonical row (`share_state`); a copy queued by `SCM_RIGHTS` is refreshed from that row when it is received or dropped.
- **`accept` is race-safe.** A connection is taken out of its listener's queue under that stack's lock, so two holders (or threads) never get the same one; the listener's state (`lid`) never changes after `listen`, so there is nothing to publish. A connection taken by a holder whose listener was closed meanwhile is reset.

Until lane fdgaps (2026-10-13) a second copy meant a double free of the handles, so fork skipped inet and listening sockets (the child had no descriptor for them), `dup` answered `EINVAL` and `pidfd_getfd` / `SCM_RIGHTS` `EBADF`. Fork also inherits AF_UNIX listeners now (one more reference on the bound address). `syscalltest`'s `inet_fork_shared` and `pidfd_getfd_inet` cover it.

### Loopback is all of 127.0.0.0/8

The loopback interface owns the whole block, as Linux's `lo` does: the vendored smoltcp treats any `127.x.y.z` as a local address once the interface holds one, and a loopback destination is its own source address. TCP, UDP and ICMP to `127.0.0.3`/`127.0.0.5` work (nettest `lo_slash8`). `close()` right after `sendto` on a UDP, raw or ICMP socket keeps the socket as an orphan until its queued packet has left (`release_inet_socket`/`reap_orphans`; nettest `raw_close_delivers`).

### ICMP and ping

Unprivileged `socket(AF_INET, SOCK_RAW)` is `EPERM`, as on Linux; `ping` ([`userland/ping`](../../userland/ping)) falls back to an `IPPROTO_ICMP` datagram socket. smoltcp's ICMP socket has no peek, so the server keeps **one stashed datagram per socket** (`icmp_peeked`, under the stack's own lock — no new lock, no lock-order edge): a peek stashes what it dequeues, a real read takes it, `FIONREAD` reports its length, readiness counts it, and closing the socket drops it (smoltcp reuses handles, so a stale stash would leak into the next socket). ICMP shares the UDP datagram path, so `recvmsg`/`sendmsg` move one datagram over all iovecs and fill `msg_name`; `SO_PROTOCOL` reports `IPPROTO_ICMP`.

`ping` waits with `poll()` bounded by the per-packet timeout and then reads with `MSG_DONTWAIT`. It used to assume `recvfrom` was non-blocking; the kernel parks a blocking `recvfrom` until data arrives, so with no reply `ping` slept forever and never printed "Request timeout". It supports `-c`, `-W`, `-i` and prints packet loss. Signals do end a blocked `recvfrom` (`EINTR`).

### IPv6

IPv6 is built bottom-up in the same smoltcp stacks, in layers that each shipped with a guest test (`ip6test`, `udptest`, `netlinktest`, `brtest`).

- **Sockets.** `AF_INET6` TCP, UDP, raw and ICMPv6 sockets work, with a family-aware sockaddr codec, listeners and `bind`. `IPV6_V6ONLY` is honoured and the default is dual-stack: a `[::]` listener also takes IPv4 connections, shown as v4-mapped addresses (sshd listens on `[::]:22` this way). `ping -6`, `ICMP6_FILTER` and the hop-limit, traffic-class and packet-info options and control messages work. `/proc/net/tcp6`, `udp6`, `raw6`, `if_inet6` and `ipv6_route` are generated.
- **Addresses.** A NIC with IPv6 enabled gets an EUI-64 link-local `fe80::/64` address (`disable_ipv6` per interface turns it off), and `sin6_scope_id` selects the interface. Global addresses come from SLAAC: the daemon sends up to three router solicitations and a router advertisement yields the address, the on-link prefix, the default router and their lifetimes ([`ip6.rs`](../../servers/net/src/ip6.rs)). The default is router-agnostic, so it works behind QEMU's slirp router and a real one. The RA MTU option caps the NIC's IPv6 MTU, and RDNSS/DNSSL options are written into `/etc/resolv.conf` (global servers after the DHCP v4 ones, three at most, plus a `search` line), the job NetworkManager or systemd-networkd do on Linux. DHCPv6 is handled by [`dhcp6.rs`](../../servers/net/src/dhcp6.rs) (below). NIC addresses run duplicate address detection (`accept_dad`, `dad_transmits`, `if_inet6` flags); tap, veth and bridge vifs run it in [`tunbe.rs`](../../servers/net/src/tunbe.rs) (see the namespace table). DHCPv6 (`servers/net/src/dhcp6.rs`, the part of NetworkManager that acts on the RA flags): O starts a stateless Information-Request (DNS servers and search list), M a Solicit/Advertise/Request/Reply for one IA_NA address (/128, valid lifetime enforced, no T1/T2 renewal: the lease is solicited again when it ends), over UDP 546 to `ff02::1:2`; state in `/proc/net/dhcp6`; servers join the RDNSS ones in `/etc/resolv.conf`, and a link-local server is written `addr%ifname`. `/proc/net/if_inet6` lists the links of the reading task's own netns. A root-only `SIOCDEVPRIVATE` (0x89f0) ioctl on any socket (`{u32 ifindex; u32 len; frame}`) hands a frame to a NIC's receive side, so tests can play the router, a DHCPv6 server or a duplicate-address owner (ip6test).
- **DHCPv6.** The client does what NetworkManager or systemd-networkd do with a router advertisement's flags: the O flag starts a stateless Information-Request (DNS servers and search list only, refreshed after option 32 `INFORMATION_REFRESH_TIME`, default 86400 s, floor 600 s); the M flag starts a stateful Solicit/Advertise/Request/Reply exchange for an IA_NA `/128` address. The Solicit carries Rapid Commit (option 14), so a Reply carrying it binds without a Request, and a plain Reply to a Solicit is ignored as RFC 8415 requires. The lease is renewed in place at T1 (Renew to the server) and T2 (Rebind to any server); it is solicited anew only when it ends or a server answers NoBinding. The DUID is a DUID-LL of the NIC's MAC, so nothing has to be stored across boots. Servers and domains join the RDNSS/DNSSL entries in `/etc/resolv.conf`, and a link-local RDNSS server is written with its `%ifname` scope. State and renew/rebind counters are in `/proc/net/dhcp6`; `if_inet6` is per network namespace. `sin6_scope_id` is filled for `fe80::/10` peers in `recvfrom`, `accept`, `getpeername` and raw ICMPv6.
- **Neighbours and routing.** NDP resolves peers; a packet that misses the neighbour cache is parked (three frames for 2 s, solicitation sent three times) and answered with ICMPv6 address-unreachable on timeout, the IPv6 twin of the IPv4 learn-miss parking. Bridges route IPv6 between each other without NAT when `net.ipv6.conf.*.forwarding` is set, with hop-limit time-exceeded and the FORWARD hook; veth, bridge and tap in any network namespace carry v6, with default and gateway routes inside the namespace ([`fwd6.rs`](../../servers/net/src/fwd6.rs)).
- **Multicast.** The NIC accepts multicast for joined groups (the brcmf driver sets allmulti so mDNS and ND reach the stack), with `IPV6_MULTICAST_IF/LOOP`, `MCAST_MSFILTER`, `IP_MSFILTER`, `IP_MULTICAST_ALL=0` and `/proc/net/igmp6` (which also lists the solicited-node group of each address). MLDv2 listener reports (ICMPv6 143 to ff02::16) follow the same filter-union rules as IGMPv3; a v1 query switches to MLDv1 Report/Done for 260 s. IPv6 multicast sent through `lo` is copied straight into the loopback device.
- **Netlink.** rtnetlink `NEWADDR/DELADDR/NEWROUTE/DELROUTE/GETADDR/GETROUTE` take v6 (busybox `ip -6` works), `IFLA_AF_SPEC` carries the AF_INET6 flags, and `RTNLGRP_IPV6_IFADDR/ROUTE` (and the IPv4/link groups) are multicast from a diff of the live tables, so a SLAAC, static or vif change all notify through one path.
- **Path MTU and fragments.** Each network namespace keeps a path-MTU cache fed by ICMP "fragmentation needed" and ICMPv6 packet-too-big (floor 1280); TCP clamps its segment size to it and `IP_MTU_DISCOVER`/`IP_MTU` work. UDP datagrams over the cached MTU are fragmented at the source (IPv4 fragments are cut to the cached path MTU; IPv6 uses a Fragment header, one identification per datagram), v6 fragments are reassembled on receive, and `IPV6_DONTFRAG` or DO/PROBE mode gives `EMSGSIZE` with nothing sent. Entries expire after `net.ipv{4,6}.route.mtu_expires` (default 600 s).
- **Error queue.** `IP_RECVERR`/`IPV6_RECVERR` queue ICMP and ICMPv6 destination-unreachable, time-exceeded and packet-too-big for UDP sockets, readable with `MSG_ERRQUEUE` through `recvmsg`, `recv`, `recvfrom` or `recvmmsg`; DF is set on the wire for DO/PROBE only.

### nftables

`NETLINK_NETFILTER` carries the nf_tables control plane ([`nfnl.rs`](../../servers/net/src/nfnl.rs)): the vanilla `nft` binary adds, lists and deletes tables, chains, rules, and named and anonymous sets per network namespace. A batch is applied to a shadow copy and swapped in at `BATCH_END`, and the first error discards it, as in Linux. Objects are stored in resolved form (batch-local IDs rewritten to names and handles), so a dump decodes identically; an unsupported expression is refused with `EOPNOTSUPP`, so a gap is loud. The datapath ([`nftables.rs`](../../servers/net/src/nftables.rs)) runs the rules as a VM on new flows only at the prerouting, forward and output hooks, with inbound, hairpin and host-local DNAT (TCP and UDP), masquerade, and SYN parking so a DNAT target that is still resolving does not lose the first packet. Established v4 and v6 flows (including hairpin) traverse FORWARD, and ICMP and ICMPv6 errors for a tracked flow match `ct state related`. A forwarded flow that no masquerade rule rewrites (no nat chain, or a chain whose verdict is not masquerade) is routed unchanged but still gets an identity conntrack entry (v4 and v6, [`fwd6.rs`](../../servers/net/src/fwd6.rs)), so its replies and ICMP or ICMPv6 errors match `ct state related` as on Linux. A `ct ... set` expression (netavark 2.x DNAT rules) is accepted and skipped, and `ct mark` loads read 0 because no per-flow mark is kept. This is what makes netavark's `firewall_driver = "nftables"` and podman `-p` work ([containers.md](../userland/containers.md)).

### Design decisions and refuted premises

- **"aarch64 ping hangs" was the host, not the architecture.** On a Mac using `socket_vmnet`, the guest's gateway is the vmnet gateway, not QEMU's slirp address `10.0.2.2`; a ping to `10.0.2.2` leaves through the host's default route and is never answered — on x86_64 too. Forcing slirp (`LEANDROS_NET=user`) made the same image answer 4/4. The genuine bug found on the way was `ping`'s missing timeout.
- **"aarch64 on slirp never gets a DHCP lease" was the harness.** QEMU's socket chardev discards output while no client is connected; the harness disconnected at `login: `, which on a fast accelerator is exactly when the lease line printed. `/etc/resolv.conf` proved the lease every time. The harness now always keeps a full serial log from QEMU's own chardev logfile.
- **"The PC's 2 Mbit/s download" was a 64 KiB window and a polled daemon** (lane netperf). Measured on the real PC: 4464 frames in 24.7 s, nothing dropped, over a ~270 ms round trip, which is exactly one 64 KiB window per RTT; and the 100 Hz daemon added 10-20 ms to every round trip, capping even a host on the same machine at ~21 Mbit/s. The fixes are the 2 MiB window and send buffer, the interrupt/kick-driven daemon (it sleeps until smoltcp's next timer), per-socket readiness (inet sockets report a poll tag and the daemon wakes only the sockets whose readiness moved in a pass, with a broadcast at most every 100 ms as a safety net), and 256 virtio-net RX buffers (was 16) with a batched RX doorbell. QEMU aarch64/HVF host HTTP went 21.6 to 2288 Mbit/s, CDN 8.0 to 31.3; x86_64/TCG 19.5 to 514; gateway ping 19.5 to 3.0 ms; on the PC, 77 and 166 Mbit/s in the first two measurements. `netcheck` measures it (below).
- **`TCP_NODELAY` shows no measurable effect on loopback, and that is correct** (a sub-10 ms RTT: the ACK arrives before Nagle's hold matters). It matters against internet peers. The test that proves the options reach the wire counts NIC packets during idle with keepalive on (≥3 more than without).
- **Keepalive is an approximation.** smoltcp has one keepalive interval and one timeout. The mapping is interval = `keepidle` and timeout = `keepidle + keepintvl × keepcnt`, so a silent peer is dropped at exactly Linux's deadline — but probes repeat every `keepidle` rather than every `keepintvl` (with defaults, one probe before the deadline instead of nine), the timeout also covers in-flight data, and it is not armed during the handshake. Enabling keepalive on an idle socket sends one probe immediately.

## Network namespaces

`CLONE_NEWNET` gives a process its own interface table and its own smoltcp stacks. Namespace 0 (the host) keeps the original NIC and loopback stacks; every other namespace is built from the pieces below, so containers get genuine isolation, not a filtered view of the host.

| Piece | Source | Summary |
|---|---|---|
| `vif` | [`vif.rs`](../../servers/net/src/vif.rs), [`vifsel.rs`](../../servers/net/src/vifsel.rs) | The per-netns interface table. A `Vif` is a loopback, tap, tun, veth or bridge (`VifKind`); stacks come from a pool of 64 dynamic slots (`MAX_NS0_SIDS` = 24 of them usable by namespace 0). A namespace records its owning user namespace, and a "netns gone" hook frees its interfaces and the peer ends of its veth pairs in other namespaces. |
| Loopback | per netns | A real `lo` stack per namespace (not the host's), brought up by `RTM_NEWLINK`/`SIOCSIFFLAGS`; a namespace's own addresses are delivered locally (Linux local table). |
| Frame device | [`framedev.rs`](../../servers/net/src/framedev.rs) | The smoltcp Ethernet device shared by tap, tun and veth ends. |
| `/dev/net/tun` | [`tundev.rs`](../../servers/net/src/tundev.rs), [`tunbe.rs`](../../servers/net/src/tunbe.rs) | Char device 10:200. The opener's netns is pinned at `open()`. `TUNSETIFF` with `IFF_TUN`/`IFF_TAP`/`IFF_NO_PI` and `%d` templates, `TUNGETIFF`, `TUNGETFEATURES`, `TUNSETPERSIST/OWNER/GROUP`, `FIONREAD`, poll/epoll; `IFF_VNET_HDR` and multi-queue are `EINVAL`. `CAP_NET_ADMIN` over the namespace's owner user namespace is required. |
| veth | `tunbe.rs` | `RTM_NEWLINK kind=veth` with `VETH_INFO_PEER` and `IFLA_NET_NS_FD`/`IFLA_NET_NS_PID`; `CAP_NET_ADMIN` is checked in both namespaces; `RTM_DELLINK` removes both ends. A frame sent on one end lands in the peer's receive queue if it is administratively up and the MTU fits. |
| IPv6 DAD | `tunbe.rs` | Tap, veth and bridge vif addresses run RFC 4862 DAD: the address stays tentative (held out of the stack, `IFA_F_TENTATIVE` in `RTM_GETADDR`) while an NS from `::` is sent for 1 s; a conflicting NA or NS-from-`::` marks it `IFA_F_DADFAILED`. `IFA_F_NODAD` skips it. `IFF_TUN` is NOARP so it has no DAD; an L3 tun answers NS for its peer and v6 over tun works with PI ethertype 0x86dd. NIC SLAAC/static addresses have no DAD yet. |
| Bridge | [`l2.rs`](../../servers/net/src/l2.rs) | An L2 switch: `RTM_NEWLINK kind=bridge` (name, MTU, address, `AGEING_TIME`, `FORWARD_DELAY`, `STP_STATE`, `VLAN_FILTERING`), ports attach with `IFLA_MASTER` (at veth creation or `SETLINK`). The FDB learns the source MAC of frames entering a port, ages entries out at lookup, floods unknown unicast to the other forwarding ports and broadcast/multicast to those plus the bridge's own stack. A port owns no stack of its own. VLAN filtering and STP are stored and reported only. |
| NAT / forwarding | [`fwd.rs`](../../servers/net/src/fwd.rs) | Forwarding from a bridge to the NIC when `ip_forward` is on: SNAT for UDP, ICMP echo and TCP, TTL decrement, full checksum rewrite, and conntrack. |

**Netlink in a namespace.** `rtnetlink.rs` answers from the caller's netns view: `RTM_GETLINK/GETADDR/GETROUTE` dumps show only that namespace's interfaces (an early version leaked the host's), and writes are accepted: `RTM_NEWLINK/SETLINK` (up, MTU, MAC, rename, `IFLA_MASTER`), `RTM_NEWADDR/DELADDR`, `RTM_NEWROUTE/DELROUTE`, `RTM_DELLINK`, with `NLM_F_ACK` replies. Writes need `CAP_NET_ADMIN` in the namespace's owner user namespace. A "dump" is recognised only on `RTM_GET*` requests: `NLM_F_DUMP` is the same bit pair as `NLM_F_REPLACE|NLM_F_EXCL` on a `NEW`/`DEL`, and treating a `NEWADDR` with `CREATE|EXCL|ACK` as a dump suppressed its ACK and hung the client. `connect()` and `getpeername()` work on netlink sockets. Per-namespace `/proc/sys/net` entries (`ip_forward`, `ping_group_range`, `ip_unprivileged_port_start`, per-interface knobs) are honoured, and `/proc/net/nic` lists a conntrack count.

**Namespace teardown.** A dead namespace's id is free at once, but its stacks live on in a `DYING` list ([`vif.rs`](../../servers/net/src/vif.rs)) until their TCP traffic has drained: Linux keeps a socket and its netns alive past the owner's exit, and freeing the stack early dropped the process's last `write()` or the peer's unread bytes. The 2 s grace (`REAP_GRACE_TICKS`) restarts whenever the queued bytes change, capped at 30 s (`REAP_HARD_TICKS`), so a stalled peer still frees the stacks 2 s after its last progress. A stack is also kept while a UDP socket still has `send_pending()` and while a bridge peer port has queued receive frames, so a queued NAT reply is emitted before the veth goes; queued retransmits on a bridge port keep the stack alive but do not restart the grace.

**Forwarding and NAT.** The bridge's receive queue is diverted into `fwd.rs` before the bridge stack sees it. A flow is keyed on its **ingress bridge port** (so one container cannot forge another's MAC to hijack the return path); the reply is delivered to the owning port directly, bypassing the FDB. NAT source ports come from 61000-64999 and are **reserved in the namespace-0 port table**: a host `bind` to a NAT-held port gets `EADDRINUSE`, and the NAT pick inserts its entry first and then retries if the host already holds the port. TCP uses a lite state machine (SYN, SYN-ACK, established, one FIN, both FINs/RST) with timeouts of 60 s, 2 h, 60 s and 10 s; UDP entries live 30 s (180 s once replied), ICMP 30 s, swept at most once a second. ARP for the next hop is snooped on the NIC receive path and requested on a miss (up to 4 frames held per pending hop, dropped after 1 s). ICMP *errors* for tracked flows are not translated. When a container is removed, `reap` and `free_vifs` drop its conntrack entries.

**Sockets and namespaces.** Each socket holds a counted reference to its creating namespace; `accept` inherits the listener's; a send is gated on the socket's own domain and captured netns, never on the `sa_family` the user passed (a per-call re-read of user memory was an egress hole). A wildcard listener bound in namespace 0 before a bridge stack existed is adopted onto the new stack when it is built. Sockets, epoll sets and the per-fd tables follow the `CLONE_FILES` fd-table key, so a `clone(CLONE_FILES)` child sees the parent's sockets.

**Atomic vectors.** `writev`/`readv` are one operation: on a tap/tun device the whole iovec is one frame (`pasta` writes an Ethernet+IP+TCP frame as three iovecs), on datagram/seqpacket sockets one record, on a pipe an all-or-nothing write up to `PIPE_BUF`. `SIOCSIFMTU` accepts up to 65535, and `getsockopt(SOL_TCP, TCP_INFO)` returns a 104-byte prefix with state and constants.

## AF_UNIX

### What is implemented

- `SOCK_STREAM`, `SOCK_DGRAM` and `SOCK_SEQPACKET`; pathname sockets bound to real VFS nodes (tmpfs only) and Linux abstract-namespace addresses; `socketpair`.
- **SCM_RIGHTS** fd passing (up to `SCM_MAX_FD` = 253 per message) and cmsg flags (`MSG_CTRUNC`, `MSG_CMSG_CLOEXEC`). VFS descriptors and lifted socket entries travel through one `XferFd` transfer type, so a socket fd — including a *listening* one — can be passed. A sender that would push a connection's in-flight fd count past 1024 gets `ETOOMANYREFS`.
  A connected-but-not-yet-accepted unix socket can be passed (it was `EBADF`), and a passed pending connector is reset when its listener closes unaccepted; sshd's forward fd-pass retry for this was removed.
- **`SO_PEERCRED`** with each end's credentials captured at connect time (D-Bus `EXTERNAL` auth and init's power-off authorisation depend on it), and **`SO_PASSCRED` / `SCM_CREDENTIALS`**: the sender's pid/uid/gid ride with the message and are translated at `recvmsg` into the receiver's pid and user namespaces; explicit credentials are checked like Linux's `scm_check_creds`. `SOCK_SEQPACKET` frames before `accept`, and `connect` through an `O_PATH` socket fd, work (container runtimes attach that way).
- `listen()` under Linux's own gates, in Linux's order: a type that cannot accept is `EOPNOTSUPP` (checked before the address, so even a bound `SOCK_DGRAM` socket gets 95), an unbound or connected socket is `EINVAL`.
- `accept4()` honouring `SOCK_NONBLOCK`/`SOCK_CLOEXEC`, well-formed peer sockaddrs from `accept()`, `F_SETFD`/`F_GETFD` on socket fds, `FIONBIO`, `FIONREAD`/`TIOCOUTQ`.
- **`connect` checks permission**: search on every directory of the path and write on the socket inode, as on Linux (root bypasses).
- Writes on a connected-but-not-yet-accepted stream are buffered; pending connections survive `fork` and are refcounted on close; connections stay alive until the last fd reference closes.
- A full send ring returns `EAGAIN`, never `0`.
- **`shutdown(2)` is a per-direction half-close**, not a teardown: `SHUT_RD` makes later receives report EOF and the peer's sends raise `EPIPE`; `SHUT_WR` the reverse; neither invalidates the fd.
- `dup` of a listening socket works: bound addresses are refcounted, so two fds share one listening queue and the address survives until the last closes.
- `read()`/`recv()` on a stream with queued fds stops at the fd batch's boundary and closes the fds when the call has no control buffer (`recvmsg` sets `MSG_CTRUNC`); `MSG_PEEK` copies bytes without consuming them and, with a control buffer, installs new references to the batch's fds while leaving it queued.
- **Garbage collection of in-flight cycles** (`unix_gc`, Linux's `net/unix/garbage.c`). An end whose only references are its own queued in-flight copies is a candidate; everything reachable from live ends' receive queues is marked; unreached candidates' queues are purged, which frees the connections through the normal close path. Listeners are graph nodes too, with their embryonic connections as edges, so a listener passed into its own backlog is collected and its address released. Without it, a socket sent over itself leaked a connection slot forever (600 rounds exceeded the 512-slot pool).

### Design decisions, and how the bugs presented

The AF_UNIX work is the clearest example of the project's "match Linux exactly" rule paying for itself, because the symptoms appeared many layers above the faults.

- **`0` instead of `EAGAIN` desynchronised Wayland.** A stream `send` on a full 4 KiB ring returned `0`, which a client cannot distinguish from a zero-length write. libwayland busy-looped in `wl_connection_flush` with its tail unadvanced, and under cosmic-panel's heavy multi-fd traffic the stream was corrupted — surfacing as an inexplicable `Unknown id 636` protocol error in the compositor. It is very likely also the original "slow vs. stuck" ghost of an early desktop milestone.
- **`shutdown` ignored `how`.** It emptied the fd-table slot, which made `shutdown(fd, SHUT_WR)` *strictly more destructive than `close(fd)`*. tokio issues `SHUT_WR` from `OwnedWriteHalf::drop`; cosmic-session's environment handshake depended on it, and for weeks the stall was recorded as a "tokio integration residual" and worked around with a 5 s timeout patch to cosmic-session. Fixing the kernel let the patch be deleted and the vendored source restored to upstream; the component cascade now starts 2.186 s after `Starting cosmic-session` instead of 5.022 s.
- **A failed `dup` killed the panel.** `wp_security_context_v1.create_listener`, which cosmic-panel calls for any applet with `X-HostWaylandDisplay=true`, marshals a *listening* socket, and libwayland dups every fd it marshals. `dup` of a listener was `EINVAL`, and a marshalling failure poisons libwayland's *whole* connection, so the error propagated out of `event_loop.dispatch()` and cosmic-panel exited 1. The bar vanished entirely — which reads as "the applets did not render" and is nothing of the kind. The same path also needed SCM_RIGHTS to carry socket fds at all, and pending connections to survive the `fork` that `launch-pad` performs at the moment an applet's privileged socket is pending.
- **The ring grows instead of staying at 4 KiB.** A fixed 4 KiB ring filled in about 100 ms under cosmic-workspaces' ~40 KB/s capture loop whenever cosmic-comp was briefly busy, and the client's `flush().unwrap()` panicked on `EAGAIN`. Rings now grow on demand (linearised, doubling) up to Linux's default `net.core.wmem_default` of 212 992 bytes and drop back to nothing once drained.

### Limits

The connection pool (512) and bound-address pool (512) are global; a COSMIC session holds about 110 connections and each terminal adds about 5. When the pool is empty the server prints `[NET] unix connection pool FULL` once. Socket tables per process grow with use (they were 455 entries in one 32 KiB order-3 block until lane fdmax); per-socket state that only some sockets need still goes in side maps rather than `SockEntry`.

## /proc/net

[`procnet.rs`](../../servers/net/src/procnet.rs) generates the Linux formats so stock tools work: `route` (default-gateway discovery the way `route -n`/`netstat -r` do it), `dev` (per-interface counters), `tcp`, `udp`, `unix`. IPv4 addresses are `%08X` of the network-order word; the `inode` column is the socket's open-file-description id (there is no sockfs); `uid` is the effective uid of the owning process. The VFS calls the generator on every open and parks the bytes in an ephemeral snapshot.

## Limitations and open work

- **No packet sockets** (`EAFNOSUPPORT`). Netlink is `NETLINK_ROUTE` and `NETLINK_NETFILTER`. IPv6 gaps: no DHCPv6, a v4-mapped destination on a v6 ping socket is `EINVAL`.
- A UDP datagram to a dead on-link peer delays later sends from that socket by up to 3 s (Linux: not at all).
- **virtio-net RX has no interrupt** (the daemon is woken by sends and polls at 100 Hz idle, 1 kHz while frames flow); r8169 has a real RX interrupt. **r8169 RX stalls (fix needs PC confirmation):** on the PC (boot 16) the receive path stalled and the watchdog reset the chip at about 235 s and 245 s of uptime, both times with RxDescUnavail and RxFIFOOver latched in `IntrStatus` (`00d4`) and enabled in `IntrMask` (`807b`) but no overflow interrupt counted. That is a dead MSI: the ISR masked only RxOK and acked only the bits it had read, so an enabled event latched in between (FIFO overflow right after descriptor-unavailable) kept `IntrStatus & IntrMask` non-zero and no later event made a new MSI edge; nothing else acked those bits. Lane r8169irq made the protocol Linux's (ISR: mask all, ack exactly what was read, kick; `rx_rearm`: unmask, re-read status, poll again if enabled work is pending, ack latched bits outside the mask; RxDescUnavail/RxFIFOOver no longer enabled on 8168 parts and never a reason to reset), modelled in `drivers/r8169-tests`. The watchdog stays as the last resort and now tells a starved daemon (frames waiting: no reset) from a stopped chip (soft recovery, then reset). Grep the PC log for `[r8169] stats` (`irq recheck rescued`) and `RX stall` / `RX backlog` ([pc.md](../hardware/pc.md#ethernet-realtek-r8169), [TODO.md](../../TODO.md)).
- An **AF_UNIX** socket shared by fork or `dup` before it is bound or connected does not share what happens next: the holder that binds or connects changes only its own copy (its bound address and connection end are refcounted per holder, so `share_state` copies inet states only).
- `O_NONBLOCK` is kept per entry, not per open file description.
- `SO_ERROR` reports a refused or ICMP-ended TCP connect and a connected UDP socket's ICMP error, not a reset or timeout.
- No `SO_LINGER`.
- UDP: an `IP_PKTINFO` cmsg on `sendmsg` is ignored (the socket's own source address is used); IGMPv3 and MLDv2 reports are sent (`igmp3.rs`, `mld2.rs`) on the NIC and tap/tun/veth stacks; `lo` is IGMPv3 too (`/proc/net/igmp` shows V3) but sends no IGMP; multicast only reaches a socket that has a socket on that interface's stack (wildcard servers do; a socket bound to port 0 lives on one stack). The local copy of a multicast or broadcast datagram is one frame and is never fragmented.
- TCP `connect(AF_UNSPEC)` aborts the connection (an RST once synchronized) and leaves the socket unconnected (it may connect again, keeping only what `bind` named), and stops a listener, as Linux's `tcp_disconnect`.
- `getsockopt` answers `ENOPROTOOPT` for `SO_ACCEPTCONN`, `SO_LINGER` and the `IP_*` options (`TCP_INFO` returns only a 104-byte prefix); add each when a real caller needs it. `TCP_USER_TIMEOUT` is not implemented.
- Clearing `TCP_NODELAY` on a connected socket does not flush (moot: the next tick sends anyway).
- A raw ICMP receive returns the ICMP message without Linux's 20-byte IPv4 header; `/proc/net/raw` has no ICMP rows.
- `mknod(S_IFSOCK)` is `EPERM` for everyone (Linux allows it unprivileged).
- nftables: filter chains run on new flows only; ICMP errors quoting hairpin flows and local time-exceeded replies are not run through FORWARD (see TODO.md).
