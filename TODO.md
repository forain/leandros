## Missing features

### Kernel
- **nitrox86 changed PIT detection** (port 0x61 bit5 must read low right after programming ch2): verify on the real laptop/PC.
- fanotify: `FAN_MARK_MOUNT`/`FAN_MARK_FILESYSTEM` cover the marked path's subtree, not a real mount-root lookup; FID events (CREATE/DELETE/ATTRIB/MOVED/RENAME) are accepted on `FAN_MARK_FILESYSTEM` only (`FAN_MARK_MOUNT` keeps `EINVAL`, as on Linux). `open_by_handle_at` reopens only handles issued this boot (a per-VFS table of issued handles → path, not a per-filesystem inode-number lookup: a renamed file gives `ESTALE`; generation is always 0). `FAN_OPEN_EXEC` (non-perm) does not also raise `FAN_OPEN` on the exec'd file; `FAN_RENAME` goes to directory and filesystem marks only (not to a mark on the renamed object).
- inotify: no (dev, ino) identity for path-keyed watches yet: no self events through a second hard link (fanotify marks share the same path keying).
- **Interrupt paths**: virtio-input, virtio-net, virtio-gpu control queue and virtio-blk (hybrid: spin `virtio_blk.spin_us`, default 50 us, then park on the completion IRQ) are interrupt-driven. Open: virtio-blk hybrid not measured on x86_64 KVM (aarch64 HVF dd 256 MiB conv=fsync, qemu CPU-s per 768 MiB: hybrid ~3.2, pure spin ~6.1, pure park ~4.1; throughput hybrid >= spin > park, noisy on a shared Mac); virtio-snd TX stays tick-pumped (the 100 Hz pump must run anyway, an IRQ gains little).
- **Synthetic sysfs**: `/sys/class/drm`, `/sys/class/input/event{0,1}` and the `/sys/dev/char` node files are staged on disk (static); hot-plugged evdev nodes (event2+) have no `/sys/class/input` entry (the libudev shim learns them from `/dev/input/hotplug`), and `capabilities/*` for event0/1 are fixed approximations. Everything else outside `/sys/class/block` stays disk-staged.
- **sshd**: privilege separation P1-P4 are done: vendored russh 0.64.1 (`userland/sshd/vendor/russh`, signer hook, `auth_publickey_signed`), the listener re-execs one `sshd -R` per connection (crash isolation, MaxStartups, LoginGraceTime kill), and each connection is split into a root monitor plus a uid 22 net child (chroot /var/empty, NNP, seccomp kill filter incl. socketpair and mlock/munlock, no host-key fd), gated by the sshsmoke `privsep_*` steps. Docs done (`docs/design/sshd-privsep.md`). Remaining: RSS/throughput numbers; also the listener backstop for a stalled monitor and `close_range` before the id drop. Not implemented: `-D`/streamlocal specific handling, `AuthorizedPrincipalsFile`, `RevokedKeys`, `Match Host/LocalAddress/RDomain`. `environment=` with `PermitUserEnvironment yes` and the `$sha256$` rehash write path of a read-only `/etc` are unverified live (the `yes` case needs a second sshd config). Still open: after the pre-auth `sshd -R` child is killed from outside (SEGV or KILL, while a login session is also live) a raw client socket never sees EOF (not within 28 s), although the process is gone, the listener is unchanged and new logins work (sshsmoke `privsep_crash_isolated` reports `probe_eof=False` as KNOWN-OPEN, does not gate). Not the accept path: the listener drops its accepted-socket copy right after spawn, and nettest `tcp_kill_closes*` (fork, SIGKILL/SEGV, extra thread, thread blocked in epoll_wait) all pass, so the kernel closes plain sockets of killed processes. Evidence from /proc/<listener>/fd after the failure: the listener still holds an unexpected extra socketpair end (fd 14) and 3 pidfds, i.e. the victim's `spawn_child` task never finished; suspect the dead child is not reaped (tokio pidfd/SIGCHLD wake missing for an externally killed child) and its fd table survives as a zombie until reaped. Next: print the victim's /proc/<pid>/status State and the listener's waitpid result after the kill.

## Notes (not work items: by design, upstream-blocked, out of scope, or deferred by the user)

- **virtio-snd TX is reaped by the 100 Hz tick pump, not an interrupt** (by design): the pump must run anyway to top the queue up with silence (QEMU 11.x loses the refill wakeup for good on an empty stream queue), so an IRQ would add nothing.
- **smoltcp "handle does not refer to a valid socket" panic (watch)**: hardened at the source (lane smolpanic2: vendored SocketSet get/get_mut resolve a stale handle to an inert stand-in, remove() of one is a no-op; brtest `stale_race` guards it); the 2026-11-14 recurrence on lane/ip6dnat was never reproduced. If a panic with this text shows again, the stale access is in a caller that kept a handle across a stack reap.
- **Interrupt-context serial diagnostics can drop under back-pressure** (by design).
- **fd-limit fence loss**: EMFILE in a virgl client's submit kills its context (as Linux); fd headroom is the defence.
- **Host-refused `RING_IDX` submit is never completed by QEMU** (descriptors lost); Mesa cannot reach it. Do not rewrite RING_IDX kernel-side.
- **Laptop SSH came up late on two 2026-10 boots** (not reproduced in ten later boots; watch).
- **r8169 RX stalls/chip resets on the PC**: ISR-mask fix needs PC confirmation (R8169 as a loadable module also deferred).
- **One permanent COSMIC patch** (`ports/cosmic-comp/0001-toplevel-info-weak-window.patch`) until upstream has an equivalent (checked 2026-11-13: pop-os/cosmic-comp#2084 and Smithay#1562 still OPEN, PR #2095 closed unmerged - patch stays).
- **Real-PC (RTX 3070) verification deferred ~1 month** (user, 2026-10-24).
- **XWayland, accountsservice, hotplug, multi-seat** are explicitly out of scope.
- **Box farm: shipped port trees must match the ref (watch)**: box regress ships the Mac worktree trees and box build-all rejects a tree whose `.srchash` differs from the ref port sources (box cannot rebuild container ports: no binfmt).
